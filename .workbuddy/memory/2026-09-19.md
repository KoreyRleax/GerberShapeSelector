### 8. 画布右上角图层容器（已完成）

**关键约束（读控件库源码才发现的）**：`AttachOverlayToolbar` 是**单浮层 API** ——
`KWindowControl.cs:360` 的实现第一句就是 `DetachOverlayToolbar()`，且只用一个 `_toolbar` 字段保存。
**挂第二个浮层会把画布顶部已有的工具栏顶掉。**
→ 图层容器**不走 AttachOverlayToolbar**，改为 `kWindowControl1.Controls.Add(_layerPanel)` +
手动定位右上角（`RepositionLayerPanel()`，并在画布 `Resize` 时重算）。
代价：没有"视口让位"（容器会压住右上角的图）和"滚轮转发" —— 前者影响小，后者把鼠标移开即可。

**容器外壳复用 `OverlayToolbar`**（它本身就是 `FlowLayoutPanel`），只把 `FlowDirection` 从
`LeftToRight` 改成 **`TopDown`**，就得到纵向列表，同时白拿它那套半透明底 / 淡边 / 正确的透明链
（它已 `SetStyle(SupportsTransparentBackColor)`）。

**每行是自定义的 `LayerRowControl : Control`**（MainForm.cs 内嵌私有类）：左文件名 + 右复选框
（自绘方框 + 两笔折线勾）。**不用 `CheckBox`** —— 它和 `Button` 一样不支持透明背景
（同样没声明 `SupportsTransparentBackColor`），放在黑画布上会是一块不透明方块。
做法照搬 `OverlayToolbarButton`：`SetStyle(UserPaint | AllPaintingInWmPaint | OptimizedDoubleBuffer |
SupportsTransparentBackColor | ResizeRedraw)` + `BackColor = Color.Transparent` +
`OnPaintBackground` 只调 base。测量与绘制**统一用 `SystemFonts.DefaultFont`**，
否则量出来的行宽和实际画出来的文字对不上。

`RefreshLayerPanel()` 重建时**先 Dispose 旧行** —— 只 `Controls.Clear()` 不会释放控件对象，换工程就漏一批。

### 9. 目录选择对话框升级（已完成）

用户反馈 `FolderBrowserDialog`（Vista 前的老式树形选择器：无地址栏、不能粘贴路径、不能搜索）难用，
要换成现代的"选择文件夹"。

**net48 没有 `FolderBrowserDialog.AutoUpgradeEnabled`**（那是 .NET Core 3.0+ 的属性），只能自己调 COM。
新建 **`FolderPicker.cs`**（已加入 csproj 的 `<Compile Include>`）：

- `CLSID_FileOpenDialog` 建对象 → 取 **`IFileDialog`** → `SetOptions(FOS_PICKFOLDERS | FOS_FORCEFILESYSTEM | FOS_PATHMUSTEXIST)`
- **不必声明 `IFileOpenDialog`**：`FOS_PICKFOLDERS` 是 `IFileDialog::SetOptions` 的选项，
  它追加的 `GetResults` / `GetSelectedItems` 只有多选场景才用得上 —— 接口声明少一半
- `Show` 声明为 `[PreserveSig] int`，以便识别"用户取消"（HRESULT `0x800704C7`）而不抛异常
- 起始目录用 `SHCreateItemFromParsingName` → `SetFolder`（失败不影响主流程）
- ⚠ **接口方法的声明顺序 = 原生 vtable 顺序，错一个就是访问冲突（进程直接挂，try/catch 拦不住）**，
  所以逐条照抄 shobjidl_core.h，不要增删调序
- 整段 try/catch 包住，任何 COM 异常降级回 `FolderBrowserDialog`，保证功能不缺失
- `GetDisplayName(SIGDN_FILESYSPATH)` 拿真实路径；`FOS_FORCEFILESYSTEM` 防止返回"库/此电脑"这类虚拟项

**已接入两处**：「打开工程」和「另存到」—— 整个程序里的选目录体验保持一致。

## 12. 修复「保存后底图消失」+「打开工程后选点不见了」（已完成，编译验证）

**证据来源：实机日志**，`bin\x64\Debug\logs\2026-09-19.log` 11:35~11:40 那几段把因果链全记下来了。
**排查日志是最快的路 —— 比读代码猜快一个量级**，这两条现象的每一步都能在日志里对齐。

### 12.1 现象一：保存后 Gerber 底图消失
**根因：「显示底图」开关在两套绘制路径下口径不一致。**
- `DrawGerberMode` 原来**无条件**画底图 → 该 toggle 在 Gerber 模式下是**死按钮**（按下画面不动、
  状态栏也不动，用户以为坏了），但 `_showBaseLayer` 已经翻成 `false`
- `DrawTemplateMode` 才读这个开关
- 「保存」→ `SaveTemplateToPathWithStateUpdate` 里 `_isTemplateMode = true` → 绘制切到模板模式
  → **那个迟到的 `false` 突然生效** → 底图消失

**修**：`DrawGerberMode` 也判 `_showBaseLayer`（两处口径统一）；两个模式的绘制**顺序**对齐为
**底图 → 选点 → 框选限定框**（模板模式原先把底图放最后画，等于把光圈描边叠在选点上层，
"保存前/后"观感不同）；`SetShowBaseLayer` 补 KLog + 状态栏回执。

**教训（可直接复用）**：**同一个状态位被两条绘制路径读到，就必须在两条路径上口径一致。**
"某模式下开关不生效"不只是个 UI 小瑕疵 —— 它会**攒下一个延迟生效的状态**，
在模式切换时炸出来，而模式切换又藏在"保存"这种看起来无关的动作里。

### 12.2 现象二：打开工程后选点不见
**两处叠加：**
1. `SaveTemplateFile` 的落点判断写成 `_isTemplateMode && _currentTemplatePath 非空`，
   而 `_isTemplateMode` 在「打开工程」时 = `restoredSelection`（**该目录里读没读到 circles.json**）。
   → 打开一个**还没存过选点**的目录（原始素材目录正是这种），编辑完点保存，
   **不写回打开的目录，跑到参数设置的模板路径下另起一份**（日志 11:39:22 那句
   `在设置路径创建新模板: ...\template\Gerber_PCB1_2025-11-24` 就是它）
2. 「上次工程」**只有「打开工程」才记录，保存不记录** → 下次开机恢复旧目录 → 那里没有刚存的选点

**修**：落点只看 `_currentTemplatePath` 是否指向真实存在的目录；`SaveTemplateToPathWithStateUpdate`
与 `SaveTemplateAs` 成功后都调 `RememberLastProject("template", targetFolder)`。
