## GerberParserSmartV4.0 —— 多图层选点两处 bug 修复

用户报了两个现象，根因都出在**多图层叠加后的判定口径**上。

### 现象 1：选点只能选到"最大圆圈"那个图层
- **根因**：`ShapeQuery.HitTest` 只按"点到边界距离最近"取胜者，而**圆内部的边界距离 = `len - r`，
  直径越大这个值越小** → 同一位置上的大圆永远赢过压在它上面的小图形。
  真实板子上 GBL / GBS 常在同一坐标放直径差很大的焊盘，于是"不论点哪儿，选中的都是大圆那层"。
- **修**：`HitTest` 增加可选参数 `Func<SelectedCircle,int> layerDepth`（**数值大者靠上层**），
  排序键改成**两级**：先比叠放，同一层内再比距离。
  新增 `ShapeQuery.SkipDepth`（`int.MinValue`）= 该图形本次不参与命中。
- **方针由用户拍板**：**穿透** —— 最上层在该处没有图形就落到下一层；
  不采用"仅最上层可点"（那会让下层整层点不动）。
- **层序口径由用户拍板**：按**画面最上层**（= 后加载 = `_layers` 末位）。
  图层容器列表顺序**保持不动**（它第一行是最先加载的、画在最底层的那层，与画面层序相反 —— 已记进文档遗留）。

### 现象 2：图层隐藏后，它的选点还画着、还能点中
- **根因两处**：① 选点是**独立于底图**画的第二遍 —— 底图那一路（`DrawGerberApertures`）过滤了显隐，
  `DrawSelectedCircles` / `DrawAllTemplateCircles` 这两处漏了；② 命中测试只认几何、不认图层。
- **修**：新增 `IsShapeLayerVisible()` 统一口径，接在四个地方：
  绘制 2 处 + 命中（`DepthForHitTest` 返回 `SkipDepth`）+ 框选（`GetCirclesInSelectedRegion`）
  + 多选扩散（`HandleMultipleSelect` 搜索范围的第一道过滤）。
- **数据不删**：`_selectedCircles` 与 `_apertures` 都不动 → 包围盒不跳、视图不晃；
  重新勾上图层，选点原样回来（隐藏是临时视觉操作，不该顺手删掉用户选的几千个点）。
- **顺带修**：多选扩散的第二道过滤原来写的是 `allShapes.Where(...)`（在**原集合**上过滤，
  会覆盖掉第一道），改成链式 `searchSource.Where(...)` —— 两道过滤才是叠加关系。

### 新增的图层查找表
`_layerDepthMap`（图层名 → 序号）+ `_hiddenLayerNames`（隐藏集合），由 `RebuildLayerLookup()` 重建。
调用点两处：`RefreshLayerPanel()`（覆盖所有载入 / 切换工程路径 —— 调用位置刻意放在**早退之前**）、
`OnLayerRowVisibilityChanged()`。
作用：把"这个图层可见吗 / 排第几层"从 O(图层数) 的字符串比较降到 O(1)（1.5 万图形 × 10 图层 = 15 万次/帧）。
**漏调的症状是"滞后"而非崩溃** —— 图层刚隐藏，点击却还能选中它。

### 踩到的坑：Edit 工具会把整个文件写成 LF
`ShapeQuery.cs` 改完变成**全 LF**（216 行），而本仓库 `core.autocrlf=true` → 工作区应为 CRLF
（`git ls-files --eol` 显示 `w/lf`）。用 PowerShell 归一（先 `\r\n`→`\n`，再 `\n`→`\r\n`）
+ `UTF8Encoding($true)` 写回，复验为 `w/crlf`、BOM 保留。
**但 `MainForm.cs` 同样走 Edit 却保持住了 CRLF** —— 说明这不是必然，**每次改完都要用
`git ls-files --eol` 复验**，不能想当然。
（`GerberParserV4.0_交接文档.html` 在仓库外，本身是纯 LF + 无 BOM，不受影响。）

## 第二轮（同一天 —— 用户反馈"仍然只能选最大圆圈的"之后）

### 用户新增的两个诉求
1. 图层容器里加**「置顶」按钮**：点击后该图层置顶，并在列表排到首位；
2. **同类扩散只在当前点击那一层内**进行。

### 第一版修复为什么可能没生效：拿"图层名字符串"关联图形与图层太脆
第一版是"用 `shape.Layer` 去 `layer.FileName` 匹配出来的字典里查深度"。
只要有一处对不上（老数据、命名差异、以后改命名规则），**所有图形都成了"未知图层"**，
`DepthForHitTest` 一律返回 -1（全相同）→ **静默退回纯距离排序** → 又回到"怎么点都只选到大圆"，
而且没有任何报错可查。

已核实的两点（说明不是名字源头的问题，而是这条链路本身不该赌）：
`displayName = Path.GetFileName(path)`（与 `LayerInfo.FileName` 同源）；
`GerberParser.ParseFile` 开头就 `Reset()` 清了 `apertureDict`，所以不会跨层污染 `Layer`。

**改法：状态直接落在图形对象上，全链路不做字符串匹配。**
- `SelectedCircle` 新增三个运行期字段（属性初始化器，不进 circles.json）：
  `LayerId` / `LayerDepth` / `LayerHidden`
- `LayerInfo` 新增 `Id`（会话内唯一，**置顶重排不变**）与 `ColorIndex`（配色，同样不随重排变）
- `BuildAllShapes` 用 `Dictionary<Aperture, LayerInfo>`（**对象引用**做键）建立归属，写 `LayerId`
- `RefreshLayerState()` 统一把深度 / 隐藏状态拷进每个图形；
  调用点：`RefreshLayerPanel()` 的早退**之前**、`OnLayerRowVisibilityChanged()`、`MoveLayerToTop()`
- `DepthForHitTest(s)` = `s.LayerHidden ? SkipDepth : s.LayerDepth`（纯字段读取，无匹配）
- 构建日志补了"**归属失败 N 个光圈**"—— 非 0 就说明归属断了，这是最快的自检信号

### 新增：图层置顶
- `LayerRowControl` 加「置顶」按钮：整行是自绘的，再切一块区域出来。
  **从 `OnClick` 换成 `OnMouseDown`** —— 一行里有两个可点区域，必须按坐标分流，
  Click 在 MouseUp 才触发、拿不到可靠的分区语义。
  已是最上层的那行**不画按钮**（点了没作用，画出来只会误导），但**位置照留**，保证复选框纵向对齐。
- `MoveLayerToTop(idx)`：把图层移到 `_layers` **末位**（= 最后绘制 = 压在最上面）。
- **容器改为倒序填充**：首行 = `_layers` 末位 = 画面最上层，与画面叠放一致 ——
  这样"置顶 = 排到首行"这句话才成立（原来首行是最底层，两者恰好相反）。
- 行宽统一取最大值（`MeasureRowWidth` 改 `public static` 供 RefreshLayerPanel 调用），否则复选框左右参差。

### 顺序持久化（不然每次开工程都要重新置顶）
- 保存端 `TemplateInfo.Layers` 加 `ColorIndex`（**v2.3**）；数组顺序本身就是图层顺序。
- `ApplyLayerVisibility` 重写：按清单顺序**重排 `_layers`**，再恢复显隐与 `ColorIndex`；
  清单里没提到的图层（工程目录里新加的文件）保持相对顺序追加到后面。
  老文件没有 `ColorIndex`，dynamic 访问会抛 `RuntimeBinderException` → 单独 try 包住，退回 -1。

### 同类扩散限层
`HandleMultipleSelect`：`c.ID == clickedShape.ID && c.LayerId == clickedShape.LayerId`。
光圈 ID 只在单个 Gerber 文件内有意义 —— GBL 的 D10 与 GTS 的 D10 是两个不同的焊盘。

### 诊断日志（排查完可整段删除）
- `LogHitDiagnostics(x, y, tolerance, chosen)`：列出光标附近图形的"图层#深度"，**按深度降序**排，
  命中者应当是第一个 —— 不是第一个就是优先级有问题；所有深度都一样就是归属没接上。
  还会报"图层总数"（= 1 时特别标注，那种情况下"叠放优先"无从谈起）。
- `LogLayerOrder()`：载入工程、置顶后各记一次"图层叠放顺序（从最上层到最下层）"。

### 验证
`dotnet build -c Debug -p:Platform=x64 -p:OutputPath=<仓库外 tmp>` 共跑 4 次（每轮改动后），
全部 **0 warning / 0 error**；`git ls-files --eol` 复验 `MainForm.cs` / `ShapeQuery.cs` 仍为 `w/crlf` + BOM。

## 第三轮（用户跑了回归测试 + 提出图标化 + 追问 JSON 结构）

### 回归测试结果（`bin\x64\Debug\logs\2026-09-21.log`）
**分层命中确认生效 ✓**。日志里"选点诊断"整片都是 `→ 命中 top.o#5`（最上层），
置顶后立刻变成 `→ 命中 smt.o#5` / `drl.o#5`，与置顶操作严格对应 ✓。

实测时间线（同一块板，6 图层 / 20188 图形）：
- **载入工程**：05.992 → 06.566 = **574 ms**，其中解析 6 个文件 410 ms、
  `RebuildAperturesFromLayers + BuildAllShapes + RefreshLayerState` 合计 **12 ms**
- **恢复选点**：09.525 → 09.727 = 202 ms，其中 **150 ms 白花在一个异常上**（见下）

### 日志暴露的真缺陷：图形唯一键缺"尺寸"这一维
日志指纹：`从 circles.json 恢复 2 个选点` + `复用选点对象 **8** 个` —— **复用数 > 已选数**，
说明同一个选点对象被反复认领、真正的图形整个消失。

根因：`ShapeKey = 图层 + 坐标 + 形状`，**没有尺寸**。同一图层、同一坐标、同一形状、直径不同的
两个圆（焊盘与它的外形框常常都落在中心点上）会算出同一个键 → 建索引时互相覆盖。
后果不是"少画一个"而是**错位认领**，症状是"那个点怎么都点不中"。

修：
- 新增 `GetSize(shape, diameter, width, height, rotation, out sizeX, out sizeY, out sizeR)`
  统一把各形状的尺寸折成三元组（圆→直径,直径,0；矩形→宽,高,0；椭圆→宽,高,旋转）
- `ShapeKey` → 7 元组（+ sizeX/sizeY/sizeR），坐标也统一 `Math.Round(...,4)`（与保存端同精度，
  于是 json 恢复的选点也能走**精确键**，不再只靠 loose 键）
- `ShapeKeyLoose` 同步加尺寸
- 各加两个便捷重载：`ShapeKey(SelectedCircle)` / `ShapeKey(Aperture a, double x, double y)`
- **`usedSelected` 兜底**：`HashSet<SelectedCircle>`，保证每个选点对象最多被复用一次，
  键即使再撞也只会"多建一个图形"而不是"重复认领"
- `IsSingleShapeInShapes` 补 **LayerId** 维度（原来只比坐标+形状+尺寸，跨图层同坐标的点会被
  判成"已经选过"而加不进 `_selectedCircles` → 选了保存不进去）
- 构建日志加自检：`复用数 > 已选点数` 时追加 ⚠ 提示

### "加载慢 150 ms"是我自己引入的（已修）
`ApplyLayerVisibility` 里用 `try { layer.ColorIndex = (int)item.ColorIndex; } catch { ... }` 兜
"v2.3 才有的字段"。打开**老工程**时每个图层抛一次 `RuntimeBinderException` ——
异常构造 + DLR 绑定失败都很贵，6 个图层 = **150 ms**，正好压在"打开工程"的关键路径上。

修：改用 `JToken` 的**索引器**取字段（`item["ColorIndex"]` 取不到返回 null，不抛异常），
顺带把 `IsVisible` 也改成类型检查后取值。需要 `using Newtonsoft.Json.Linq;`。
方法签名仍是 `dynamic`（调用方传的就是 JObject，`as JToken` 成功）。

> 教训：**用异常探测"字段在不在"是昂贵的**。Newtonsoft 的 JToken 索引器天生返回 null，
> 没有理由用 dynamic 点属性 + try/catch。

### 置顶按钮 → 图标
`LayerRowControl` 里的「置顶」文字换成**几何自绘的向上箭头**（实心三角头 + 短箭杆，
`FillPolygon` + `DrawLine`）—— 不赌系统装了哪个字形，也不受 DPI 缩放影响。
按钮宽 34 → 24 px。加了 `ToolTip`（字段 `_layerRowToolTip`，在 `BuildLayerPanel` 建）补文字说明，
因为图标本身没有语义。行宽仍统一取最大值，最上层那行只是不画图标、位置照留。

### JSON 导出结构（用户问）
**是多图层的**：`Shapes.Circles/Rectangles/Ovals` 每条记录都带 `Layer`（图层文件名），
一条记录一个图形一个坐标；`TemplateInfo.Layers` 数组顺序 = 图层绘制顺序。
另：`Version` 从 "2.2" 升到 **"2.3"**（因为 Layers 元素补了 `ColorIndex`）；
读取端不校验版本号，老文件照样能开。

## 第七轮（用户：图层容器加顶部栏 —— 文件名 / 置顶 / 【全选】）

### 做法（改动**只在 `MainForm.cs` 一个文件**）
1. **新增 `LayerRowLayout`（静态类）** —— 把容器里"三列自右向左"的几何抽成**一份**：
   `BoxSize` / `TopColumnWidth` / `TextWidth()` / `RowWidth()` / `TopColumn()` / `CheckBox()` / `TextAreaWidth()`。

   差 8px 就错开一格，而这类错位**只看代码看不出来**、只能靠肉眼发现 —— 抽成一处后结构上不可能错开。
2. **`TopColumnWidth` 是量出来的**：`max(24, 「置顶」文字宽 + 6)`。
   原来那列只为 ↑ 图标留了 24px，而 `SystemFonts.DefaultFont` 下两个汉字约 22~26px ——
   写死会裁字或压到复选框上，并连带把每行的文字区宽度也算错。
3. **新增 `LayerHeaderControl`**：`Control` 自绘（与图层行同一套 `SupportsTransparentBackColor`）。
   - 三段：左「文件名」、中「置顶」、右方框；文字比图层名淡一档（×0.72 alpha，黑底上对比度仍 ≥ 9:1）
   - **热区只在方框周围**（12px 框外扩 6px = 24×24）；光标只进热区才变手型；
     点「文件名」/「置顶」无任何反应 —— 整行可点会让"想看清表头"的一次误触**把所有图层全隐藏**
   - **方框三态**：全勾 → 打勾；部分勾 → 一横；全不勾 → 空。
     两态在"6 层勾了 4 层"时会显示成空或勾，**属谎报**
   - 点击行为只有两条：全勾时点 = 全部取消；其余（含半勾）点 = 全部勾上
4. **`RefreshLayerPanel()`**：表头**最先 `Controls.Add`**（TopDown 里先加的在上 = 首行）；
   `maxRowWidth` 初值改为 `MeasureRowWidth("文件名")`，保证表头不比任何一行窄。
5. **`SetAllLayersVisible(bool)`**：遍历设 `IsVisible` → `KLog` + `LogLayerOrder()` →
   `RefreshLayerPanel()`（**重建**）→ `RefreshKWindow()` → 状态栏。

### 为什么全选要重建容器、单行不用
每行的复选框是**该行控件的私有字段**（`LayerRowControl._checked`）。全选改了所有图层，
就必须让所有方框跟着变 —— 唯一同步手段是重建。单行被点的那一行自身已是最新，
重建反而会清掉鼠标下的悬停态（手感变差），所以它只 `RefreshLayerState` + `RefreshKWindow`。

- 方框只做两态 / 点击改成"反选" → 分别见上（谎报）与用户原话（要的是全选）

### 踩到的两个小坑
1. **`Write` 工具写 md 是 LF**：本次新建的 `R-20260921-02…md` 是 LF，而同目录其它 md 全是 CRLF

2. **根 README 的 ASCII 界面图**要加表头行，而图里的对齐靠**显示宽度**（汉字占 2 列）——

  → `MainForm_Load` 调用。**不建它的后果**：目录不存在时"新建工程自动落盘"会退化成弹框问位置，
  等于默认值白设。

  `btnParamSetting_Click`（参数设置里显示**解析后的绝对路径**，人看得懂）

## 第十六轮（用户裁定：不同图层同坐标的点"不被允许"）

### 用户原话

> 要么改模型，要么在用户保存时弹窗警告

这条等于给 **T13**（"下游能否接受同坐标多条"）画了句号：**不接受**。

### 先查清"两个点"从哪来（单选不会）
`ShapeQuery.HitTest` 只返回一个图形（按图层叠放取胜者），所以单选永远只点到最上面那条。
真正的来源只有三条：

| 路径 | 位置 | 为什么没去重 |
|---|---|---|
| **框选**（主因） | `MainForm.cs:3453-3469` | 判"是否已选"用四维 `ShapeKey`，跨图层同坐标是两个不同的键 → 两条都进 `_selectedCircles` |
| 隐藏上层 → 点下层 → 恢复上层 | 规则 R1「隐藏 = 数据保留」 | 看不见的旧点还在数据里，用户以为没点过 |
| 合并点 / 游离点落在已有坐标 | `MainForm.cs:1267-1277` | `CreateMergedShape` 取中点，不查全局坐标 |

而保存端 `SaveTemplateToPath` 落盘前**零查重**。

### 关键判断：这是**两套口径**，不是一套
- **图形唯一键 `ShapeKey`（四维）**：管"选点对象 ↔ Gerber 图形"的一一对应，**不能动**
  （少了图层维度会静默退回纯距离排序 = 刚修完的"只能选到大圆"）。
- **交付给插针机的落点集合**：下游按**坐标**定位、不读 `Layer`，所以口径**只认坐标**。

→ "改模型"并不需要动四维键；但最终**没走改模型这条路**（理由见下）。

3. **隐藏图层悖论**：藏起来的旧点算不算存在？算 → 用户莫名被拒；不算 → 重复照样产生。
