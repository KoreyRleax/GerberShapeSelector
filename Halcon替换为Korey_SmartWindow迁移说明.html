工程：D:\MyWork\Gerber\选点软件\高清版V4\GerberParserV4.0
控件库：D:\MyWork\Common\Korey.SmartWindow.WinForms（dll 已引入本项目 lib\）
日期：2026-09-18
结果：Halcon 依赖已完全移除。渲染改为 KWindowControl 的 GDI+ 矢量自绘， 工程内所有 HalconDotNet / HOperatorSet / HObject / HTuple / HWindowControl 引用清零 （仅注释里保留了"原来是 X、现在是 Y"的对照说明）。 控件库 API 全部对照源码逐个核实过；改动后做了静态自检：五个文件大括号全部配平、 62 个方法无重复定义、全工程零 halcondotnet 字样。

二、API 映射（实际改法）

原来（Halcon）现在（Korey.SmartWindow）
hWindowControl1.Paint += ...
里面 ClearWindow() 后全量重画		 kWindowControl1.PaintContent += OnPaintContent;
回调里用 ctx 以世界坐标画；不再需要清屏
GenCircle + ConcatenateObj + DispObjctx.DispCircle(row, col, radius)（世界坐标）
GenRectangle1 + DispObjctx.DispRectangle1(row1, col1, row2, col2)
GenEllipse + DispObjctx.DispEllipse2(row, col, phi, radius1, radius2)
SetColor / SetDraw / SetLineWidth同名方法，在 ctx 上；颜色名仍是 Halcon 那套（"dim gray" 等）
windowX = x * _halconScale + _halconOffsetX整行删除，直接传世界坐标
SetPart(0,0,H-1,W-1) + 手工 scale/offsetkWindowControl1.FitToWindow(世界包围盒)；之后由 KViewport 自持
hWindowControl1.Invalidate() + Update()（注释写着"必须刷两次"）kWindowControl1.Refresh()（一次即可）
HMouseWheel 里手工 _halconScale *= 1.1 + offset 补偿删除，滚轮缩放内建（数学等价）
HMouseDown/Move/Up 中键拖拽平移删除，拖拽平移内建
(e.X - offset) / scale 反算世界坐标删除，KMouseDown(x, y, button) 直接给世界坐标
HOperatorSet.DrawRectangle1(...)（阻塞、窗口假死）BeginDrawRectangle1() + Rectangle1Selected 事件（非阻塞）
SetMshape("crosshair")框选时控件自动设十字光标
SetSystem("tsp_width/height")、pressAltKey()（6 处）全部删除
参数顺序是刻意对齐的：DispCircle(row, col, r) 与 Halcon 的 GenCircle(Row, Column, Radius) 一致，所以迁移时只去掉 * scale + offset，不需要交换坐标轴。 代码里的对应关系是：Aperture.Position.Item1 → 世界 X（水平 / col）， Item2 → 世界 Y（垂直 / row）。

三、⚠ 交互契约变了（这条需要你确认）

控件库有一套跨项目统一的基础交互约定（README 里明确写了"所有引用方共享同一套手感"）， 所以我没有为这个工程另开一套，而是跟着库的约定走。有两个键的行为与原来不同：
操作原来现在
滚轮以鼠标为锚点缩放不变（内建）
中键按住拖拽 = 平移单击 = 重置视图（拖拽平移改到右键）
右键提示"退出选点模式"（实际没实现）拖拽 = 平移；未拖动时抛 ContextMenuRequested（目前未接菜单）
左键选点 / 取消选点不变
Esc无退出选点模式 / 取消框选（补上了原来只在提示语里承诺的功能）
Q / 空格框选 / 清除区域不变

如果你的手更习惯"中键拖拽平移"，在 MainForm.cs 里加一个子类即可，不用动库：

// 把中键改回"拖拽平移"，并关掉中键重置
kWindowControl1.EnableMiddleButtonResetView = false;

// 若还要让中键承担平移，需要派生 KWindowControl 重写 OnMouseDown

四、顺手修掉的问题（对照上一份审查报告）

编号问题处理
A1每帧全量重建几何（约 3.1 万次算子调用 / 帧） 已消除。改成 PaintContent 直接画世界坐标；并加了视口裁剪（GetVisibleWorldBounds），每帧只画落在可见区里的图形 —— 成本上限从"全图 15,359 个"变成"可见图形数"
A2每次点击重建 15,359 个对象 + 循环内 O(M) 查找（≈2,960 万次比较 / 次点击） 已消除。改为 BuildAllShapes() 一次构建 + 字典 O(1) 复用；命中测试单次 O(N) 扫描
A3多选模式同 ID 扫描 + 嵌套线性判重 命中路径已改；HandleMultipleSelect 内部逻辑保持原样（现在 allShapes 是缓存，不再每次重建）
A4翻转开启后 O(N²) 包围盒重算（2.36 亿次 / 帧） 已消除。包围盒缓存进 _contentBounds，只在解析/加载时算一次
A5选中层被重复绘制（模板模式白画两遍） 已消除。模板模式去掉冗余的 DrawSelectedCircles 调用；Gerber 模式保留（那个模式需要它）
A6"必须刷新两次" 已消除。单次 Refresh()；那个现象本来就是"重建太慢 + 与 WM_PAINT 交错"的产物
B1缩小后 GEN 半径低于 0.5px 抛异常 → 黑屏 根因消失。GDI+ 没有半径下限，也不会因此抛异常中断整帧绘制
B2_halconScale 可能为 0 → 除零 / NaN 根因消失。缩放由 KViewport 自持（含 MinScale/MaxScale 限幅），宿主不再除它
B3提示语承诺的"右键退出选点模式"没实现 改为 Esc 退出，并修正了提示语（右键现在是平移）
B5框选口径不一致（圆心在框内 vs 点落在图形内） 统一为"图形与框相交"；压线图形不再被漏掉
B6框选异常后按钮永久变灰 用 finally 恢复按钮状态；取消框选也会恢复
B7pressAltKey() 散落 6 处（含每按键都发一次 Alt） 全部删除
B8所有诊断日志在 WinExe 下丢失 改走 KLog → logs\yyyy-MM-dd.log（含异常堆栈）
B10模板保存"先删后写"，中途崩溃丢数据 改为 WriteFileAtomic（临时文件 + File.Replace 原子替换）
B11椭圆的命中检测忽略旋转 ShapeQuery.HitTest 里做了旋转坐标变换，旋转椭圆可精确命中

另外两处顺手改的行为（如果不合预期可以还原）

  • 点击容差：命中判定放宽到"至少 4 个屏幕像素"。缩得很小时，小图形原来几乎点不中， 现在点在附近就算命中。
  • 重叠图形：原来返回列表里第一个命中的，现在返回离光标最近的那个（更符合直觉）。

六、本地验证步骤

  1. 编译。用 VS 打开 GerberParserSmartV4.0.sln，构建。若报"找不到类型/命名空间"， 先把第 8 节的自查点过一遍。
  2. 打开铜层 GBL（bin\x64\Debug\Json\GBL1\1516601-00-C_01.GBL，15,359 个图形）， 看是否正常显示、颜色是否与原来一致。
  3. 拖动与缩放。右键拖拽平移、滚轮缩放、中键重置视图。重点感受：拖动是否跟手。 放大到只看得见几百个图形时应该明显更轻（视口裁剪在起作用）。
  4. 放大后的边缘质量。滚轮放大 10 倍以上，圆应当始终是光滑的圆 （这是 GDI+ 矢量重绘，不是位图放大 —— 原来"稳定版"烘焙 region 的位置会发糊）。
  5. 选点。点几个焊盘，看命中位置准不准（拖动/缩放之后再点，应当依然准）。
  6. 框选。点"框选区域"或按 Q，左键拉框：窗口应当全程可响应 （原来是阻塞式算子，框选期间整个界面假死）；Esc 或右键取消；确认取消后按钮恢复正常。
  7. 模板存取回归。依次用 Json 目录下的 7 组模板（GBL1 / GBL2 / GBS1 / MAX! / New / cjl / Max1 / Mid1 / RBL123 / RBL1231 等） 做"加载 → 保存"往返，确认 JSON 数值与原来一致。
  8. 翻转。开启水平/垂直翻转：现在应当立刻响应（原来是 O(N²)，一点就卡死）。
  9. 看日志。运行后检查 exe 同目录的 logs\，确认有内容； 若有 [ERROR]，那正是原来被 Console 吞掉的信息。

七、性能预期（推算，需你实测对照）

场景原来（推算）现在（预期）
全图视图（15,359 个图形可见）140–490 ms / 帧 视口裁剪后所有图形都可见，属最坏情况：约 30–80 ms（GDI+ 逐图形光栅化）。 若这一档仍嫌慢，可以再加"远景用位图缓存"的分级 LOD
放大到可见几百个图形140–490 ms / 帧（与可见数无关） 1–3 ms / 帧（只画可见的）
点击一次选点0.2–1 s< 1 ms
开启翻转2.36 亿次迭代 / 帧（实际卡死）与未翻转相同
要盯的指标是"全图视图"那一档。视口裁剪解决的是"放大后仍然慢"， 但缩到全图时 15,359 个图形都得画，这时的成本由 GDI+ 的光栅化速度决定。 如果你的实际用法里"全图视图"是主要工作状态，而且帧率不理想， 下一步就上分级 LOD（远景用一张预渲染位图平移、中景/近景才走矢量），我可以接着做。

八、编译不过时的自查点

  • Korey.SmartWindow.WinForms.dll 是否在 lib\ 下（csproj 的 HintPath 指向它）。
  • KWindow 类型是否解析到 —— 需要 MainForm.cs 顶部的 using Korey.SmartWindow.WinForms;。
  • 事件签名核对（库与宿主必须一致）： 
    PaintContent                 : Action<KWindow>
KMouseDown / KMouseUp        : Action<double, double, MouseButtons>
Rectangle1Selected           : Action<RectangleF>
Rectangle1Cancelled          : Action
ViewChanged                  : EventHandler
  • ValueTuple 作为字典键：本项目是 net48，已内置 System.ValueTuple，无需额外引用。
  • 若提示 Console 相关错误，说明还有漏改的 Console.WriteLine（应全部为 KLog.Info）。

本说明覆盖的改动均为静态核对结果；性能数字为推算，需以你机器上的实测为准。
