## 一、数据模型（本次裁定）

### 1.1 一句话模型

> **工程 = 一个目录 = N 个 Gerber 图层文件 + （可选）一个 `circles.json`**

`circles.json` 存在 → 这个工程有选点；不存在 → 新工程，选点为空。
**"模板"不再是一个独立概念**，它就是"有 circles.json 的工程"。

这样裁定的理由（三条）：

1. **模板和 Gerber 不是两种东西，是同一工作区的两种状态**（有 / 无选点元数据）。
   把它们做成两个按钮、两条加载路径、两套保存规则，等于把"状态"误建模成"类型"——
   代价是让用户去猜程序内部的分类。
2. **多图层让这个裁定的必要性变成硬性的**：一个目录里躺着一堆 `.GBL/.GBS`，
   再单独区分"我在打开 Gerber 还是在打开模板"已经没有意义了。
3. **用户的心智里只有一个动作**："打开这块板子的工作目录。"

### 1.2 对象图

> 下表的 `Project` / `Layer` 是**概念模型** —— 代码里没有这两个类，它们是 `MainForm` 的字段
> `_layers`（元素类型 `LayerInfo`，private sealed class）与 `_selectedCircles`。
> 已按 **2026-09-21** 的实现核对。

```
MainForm（工程 = 一个目录）
├─ _currentTemplatePath  string                工程根目录（**"工程归属"的真值**；Program.FileName 不是）
├─ _layers               List<LayerInfo>       图层，有序；顺序 = 绘制顺序（**末位画在最上面**）
│   └─ LayerInfo
│       ├─ FilePath    string                  图层文件全路径
│       ├─ FileName    string                  显示名，如 1516601-00-C_01.GBL（**同时是图形的图层标识**）
│       ├─ Id          int                     会话内唯一；**置顶重排不会改变它**（图形靠它认图层）
│       ├─ ColorIndex  int                     配色序号；载入时定下，**不随重排变**
│       ├─ IsVisible   bool                    图层容器复选框；默认 true
│       └─ Apertures   List<Aperture>          该图层解析出的光圈（含全部位置）
├─ _apertures            List<Aperture>        所有图层的扁平聚合（**给包围盒用，刻意不过滤显隐**）
├─ _allShapes            List<SelectedCircle>  扁平成一个个可点的图形（带图层状态，见下表）
└─ _selectedCircles      List<SelectedCircle>  选点集合，跨图层；**与 _allShapes 里是同一批对象实例**
```

`SelectedCircle` 除几何字段（`X/Y/ID/形状/尺寸/旋转`）外，还带四个图层相关字段：

| 字段 | 含义 | 持久化 |
|---|---|---|
| `Layer` | 所属图层**文件名**（图层身份，参与唯一键） | ✅ 进 `circles.json` |
| `HeaderType` | 该点由**哪个插针头**插：`h1` / `h2` / `h3`（默认 h1）。与 `Layer` **正交** —— 同一层上的点可分属三个头 | ✅ 进 `circles.json`（v2.4） |
| `LayerId` | 所属图层的会话内 Id | ❌ 运行期 |
| `LayerDepth` | 所属图层在 `_layers` 里的序号 —— **越大越靠上层**，命中优先级比的就是它 | ❌ 运行期 |
| `LayerHidden` | 所属图层当前是否隐藏（决定画不画、能不能选） | ❌ 运行期 |

**图层是全模型的一等公民。** 没有图层归属，两个图层在同一坐标的同形状图形会被当成同一个，
命中测试、框选、图层显隐都会算错。

**图形的唯一键（2026-09-21 起为四维）：**

```
ShapeKey = (图层, 坐标(4 位小数), 形状, 尺寸)
    尺寸由 GetSize() 统一折成三元组：圆 → (直径, 直径, 0)；矩形 → (宽, 高, 0)；椭圆 → (宽, 高, 旋转)
```

四维缺一都会**错位认领**（同一个选点对象被塞进缓存多次、而另一个图形整个消失）。
演进历程：`(X, Y, Shape)` → 加**图层** → 加**尺寸**。
使用点三处必须口径一致：`BuildAllShapes` / `ApplyRegionSelection` / `IsSingleShapeInShapes`，
详见 `MD文件汇总（AI）/问题&解决方案/重复坐标的图形互相顶替.md`。

### 1.3 四条硬规则

| # | 规则 | 说明 |
|---|---|---|
| **R1** | **隐藏图层 = 不画 + 不选 + 数据保留** | 取消勾选某图层 → 它的底图与已选点**一起消失**、点不中、框选不到、多选不扩散；但**选点数据仍留在 `_selectedCircles` 里**，重新勾上即原样恢复。⚠ **它仍会被写进 `circles.json`**（导出端不做显隐过滤）—— 取舍见 §五-3 |
| **R2** | **同位置多图形按"图层叠放"决定谁被点中** | 见 1.4。2026-09-21 起是**最上层优先、可穿透**，**不是**"整组联动" |
| **R3** | **无法解析的文件：跳过，且不在图层容器中显示** | 见 1.5 |
| **R4** | **所有能打开的工程都可修改** | 打开即进入可编辑态；保存写回 `RootPath`。没有"只读预览"这种模式 |

### 1.4 R2：同位置多图形（GBL / GBS 大量坐标相同、仅尺寸不同）

背景：`.GBL`（底层）和 `.GBS`（丝印/阻焊）经常在同一坐标放着不同尺寸的图形。
用户点一个位置时，要决定的是"**这个位置要不要**"。

> ⚠ **本节 2026-09-19 的原始裁定（"同位置多图形默认联动选中 + 导出前按坐标去重"）
> 已被 2026-09-21 的实现取代**，此处按现状重写。原始意图见 `.workbuddy/memory/2026-09-19.md`。

**当前实现 —— 按图层叠放决定谁被点中：**

- 命中测试的排序键是**两级**：先比**图层叠放**（`LayerDepth` 大者胜），
  **同一图层内**再比"点到边界的距离"；
- **最上层在该处没有图形时，穿透到下一层**（不会"点了没反应"）；
- 所以"点得到谁"取决于**图层顺序**，而顺序用户可以改 ——
  图层容器每行右侧的「↑」图标把该层移到最上层（`MoveLayerToTop`），顺序随工程保存。

**为什么不做"整组联动"**：那会让"选一个点"变成"选一列点"，用户无法只选其中一层；
且联动后导出必然出现同一坐标的多条记录，下游是否接受尚未确认（见下）。

⚠ **2026-09-21 更新 —— 用户裁定：同坐标多条 = 不允许**（原"不做导出端按坐标去重"的结论已被推翻）。
理由：插针机按坐标定位，同坐标多条就是**重复插针**。
但**没有**改成"按坐标合并"——那会吃掉"两个不同的焊盘/针位"，而且**程序猜不准该留哪一条**
（`GBL` / `GBS` 常在同坐标放**不同尺寸**的图形，插针机要打的通常是其中某一条）。于是改为在**保存端**
加一道**检出 + 弹窗**：列出每处冲突的「图层 / 形状尺寸 / 头类型」，用户选「返回修改」（一个文件都不写）
或「仍然保存」。

**图形的四维唯一键仍然不动** —— 它管的是"选点对象 ↔ Gerber 图形"的对应（少了图层维度会静默退回
纯距离排序，就是"只能选到大圆"），与"导出端按坐标判重"是**两套口径**，别混。
详见 `MD文件汇总（AI）/任务&需求/R-20260921-06-保存前同坐标重复点检查.md`。

### 1.5 R3：无法解析的文件

判据：`GerberParser.DetectFileType()` 无法识别，或解析后光圈 / 图形数为 0。

处理：**跳过 + 不进图层容器 + 导入完成后汇总提示一次**
（"3 个文件无法解析，已跳过：a.xxx、b.xxx、c.xxx"），不要逐文件弹框。

> ✅ **已修（2026-09-19）**：`GerberParserTool` 侧新增 `ParseFile(path, requireKnownType)` 重载 ——
> `true` 时 `DetectFileType` 认不出就返回 `ParseResult.CreateError`，调用方据 `result.Success`
> 干净地跳过该文件并汇总提示；原单参重载转发 `false`，**旧行为一字未变**。
> dll 28,160 → 28,672 B，引用已挪进 `lib\`。

### 1.6 circles.json 格式

**权威说明已移到 `MD文件汇总（AI）/系统架构&协议设计/数据格式-circles.json.md`**
（含 v2.0 → v2.5 完整演进、逐字段表、去重口径、**下游插针机的对接**）。此处只留两条**动这个文件时必须知道**的约定：

- **坐标直接挂在记录上**（v2.5）：`Shapes.*[].X` / `.Y`。v2.4 及以前包在 `Positions` 数组里
  （每条只放一个元素），那层是历史包袱，已去掉。🔴 **读端不兼容旧格式**（用户 2026-09-21 裁定）：
  打开 v2.0~2.4 的老工程，坐标会**全部读成 0**、点堆在原点 —— 属预期而非缺陷。
  ⚠ 打开这类老工程后**别点保存**，否则把"全 0"写回去，**不可逆**。
- **读取端走 `dynamic`**：字段拼错 / 缺失要到运行时才报错。
  ⚠ 2026-09-21 已把 `ApplyLayerVisibility` 改成 `JToken` 索引器（取不到返回 null、不抛异常），
  **坐标也新走了 `ReadJsonPosition`（JToken）**，但 **`LoadJsonFormat` 里其余字段（`SizeX` / `Rotation` /
  `TemplateInfo.*`）仍是 `dynamic`** —— 缺字段会抛异常，被外层 catch 吞成"选点文件读取失败"、
  选点全空。见 `MD文件汇总（AI）/待办/待办清单.md` T09。

当前版本号 **v2.5**（2.1 加 `TemplateInfo.Layers`；2.2 给每个图形加 `Layer`；2.3 给图层加 `ColorIndex`；
2.4 给每个图形加 `Header` = 插针头类型 h1/h2/h3；2.5 坐标从 `Positions[]` 提到记录上的 `X` / `Y`）。
读取端**不校验版本号**，老文件照样能打开。`Header` 缺失时读成 `h1`（走 `JObject` 索引器，不抛异常）。

**界面构成（与实现一致）**

1. **菜单栏**（`MainForm.Designer.cs`）：
   - **文件(F)**：新建工程... / 打开工程... / 删除工程... / 保存 / 另存到... / 退出
   - **编辑(E)**：框选区域 (Q) / 解除框选限定 / 清空选点... / 水平翻转 / 垂直翻转
   - **视图(V)**：重置视图 / 显示底图 / 参数设置...
   - **帮助(H)**：操作说明 (F1) / 关于
2. **画布悬浮工具栏**（运行时创建，**不在设计器里**）：`单选` `多选` ｜ `h1` `h2` `h3` ｜ `合并` ｜
   `框选区域 (Q)` `解除限定` ｜ `清空选点` `底图` ｜ `F1 操作说明`。挂载用控件库的 `AttachOverlayToolbar(…, ToolbarEdge.Top)`，
   控件库会自动做**视口让位**（工具栏只压留白、不压图）。
   - `h1` / `h2` / `h3`：**当前插针头类型**（互斥）—— 决定"接下来选中的点归哪个头"，三种头用不同颜色画。
     与「单选 / 多选」同构：都是"当前用哪种语义"的开关。
   - `合并`：进入合并模式后依次点两个图形 → 取**中点**生成一个新点（形状尺寸沿用第一个，原点保留）。
   - 右键菜单里也有对应项（单选 / 多选 + 切换到 h1 / h2 / h3），不必回工具栏切换。
3. **画布右上角图层容器**（运行时创建）：**首行是表头**（`文件名` ｜ `置顶` ｜ `【】`），
   其下每行 = `文件名` + `↑ 置顶图标` + `复选框`；容器**倒序显示**（表头下面第 1 行 = 画面最上层）。
   表头前两段是**纯文字**（列名），只有右边的方框可点 —— **全选 / 取消全选**（三态：全勾 / 一横=半选 / 空）。
   位置靠 `RepositionLayerPanel()` 贴到画布右上角并 `BringToFront`。
   ⚠ 它**不是**用 `AttachOverlayToolbar` 挂的，所以**没有视口让位** —— 与图像区边缘会重叠。
4. **状态栏**：左侧是消息（`toolStripStatusLabel1`，`Spring = true` 把消息推到最左），
   右侧三个信息位：`lblSelInfo`（已选数量 + 缩放）、`lblLayerInfo`（**只报工程名**）、`lblView`（可见范围）。
5. **右侧面板已删除**（`groupBox2` / `groupBox1` / `groupBox4`），画布占满横向空间；
   其中 `groupBox4`（原"图层"预留位）**至今仍是空面板** —— 图层容器实现在画布右上角，见第 3 条。

## 三、技术栈裁定：留在 WinForms

明确不考虑迁移到 WPF。理由：

- 本次要做的改动（顶部菜单、状态栏、删面板、右上角悬浮容器）**没有一样是 WinForms 做不到的**，
  难度都不高；
- 迁移成本全部落在**与需求无关**的地方：XAML 重写、`OpenFileDialog`/`FolderBrowserDialog`/`MessageBox` 全换、
  `RectangleF`→`Rect`、`MouseButtons`→`MouseButton` 逐处适配；
- 最贵的一条：画布层要从 `Korey.SmartWindow.WinForms` 换成同一个库的 WPF 分支。
  虽然 API 逐字一致，但 WPF 版**未在 15,359 图形、框选、旋转椭圆命中测试这些场景验证过** ——
  而这正是本工程的价值所在。用未验证的核心换已验证的边缘，风险不对称；
- DPI 感知这个遗留问题**不需要 WPF 解决**：.NET Framework 4.8 支持在 `App.config` 里声明
  Per-Monitor V2，"高清版"在缩放显示器上被位图拉伸的问题即可消除。
  （⚠ **尚未实施** —— `App.config` 里目前没有 DPI 感知声明。见 `MD文件汇总（AI）/待办/待办清单.md` T11）

**什么时候该重新考虑**：`Korey.SmartWindow.Wpf` 被独立验证过（有 demo 跑满 15k 图形）、
或界面开始出现大量数据绑定需求（图层属性表格、选点列表）。到那时，画布层 API 的逐字一致
保证了迁移不会太痛 —— 所以**推迟没有代价**。

### 雷区

- ⚠ **`bin\x64\Debug\Json\` 是真实使用者的工程数据，不可再生。** 清理 `bin`、重编、改输出路径前必须确认它安全。

  → 克隆仓库后直接编译不过，清空 `bin` 后同样编不过。
- 源码是 **UTF-8 带 BOM + CRLF**（`core.autocrlf=true`，工作区应为 CRLF），批量改文件必须保持。
  ⚠ 实测 Edit 工具**有时会把整个文件重写成 LF** → 改完用 `git ls-files --eol <file>` 复验。
- `LangVersion` 只在 x64 配置里显式声明为 7.3；**AnyCPU 走编译器默认值** —— 写更高版本语法会在 AnyCPU 下编不过。
- 日志：`KLog` → exe 目录下 `logs\yyyy-MM-dd.log`，排查问题**先看它**。
- ✅ **`Program.FileName` 默认值已改为 `string.Empty`**（2026-09-19 修）。原来是原开发者本机的绝对路径，
  换机必然失效，还会把本机用户名写进版本库。⚠ 但它**仍是隐式全局状态**（`MainForm` 之外也有引用），
  真正的状态源应是 `_currentTemplatePath`。

### 关键设计决策（改前必读）

- **选点不要门禁**：左键任何时候都能选点，单选 / 多选只是"点击语义"，不是开关。
- **框选 = 选择；框选限定 = 作用域**：限定只影响多选时"同类扩散"的范围，**不拦截点击命中**。
- **框外点击一律解除限定**（单选 / 多选 / 右键共用 `ReleaseScopeIfOutside`），规则只能有一条。
- **`IsSelected` 与 `_selectedCircles` 是两份状态，必须同步**；清空一律走 `ClearAllSelection()`。
- **画布背景纯黑**，光圈配色按"对纯黑对比度 ≥ 4.5:1"筛选。
- **`Color.Green` ≠ Halcon `green`**：本工程语义是 (0,255,0)，颜色转换两头都要对齐。
- **保存是就地保存**，落点必须对用户可见（显示完整路径）。
- 🆕 **落点只有两个来源**：有归属 → 就地写回 `_currentTemplatePath`；
  **没有归属 → 弹「工程名 + 保存位置」对话框，由用户当场定**
  （2026-09-21 起）。**落点里不存在任何"全局默认目录"**。
  选目录类对话框（另存到 / 新工程首次保存）的起始位置统一由
  `MainForm.GetProjectParentBrowseDir()` 给出，优先级：
  **「默认工作路径」**（用户可改；默认是**程序目录下的 `Broad`**，首次启动自动创建，
  设置项里存的是相对路径 `Broad` —— 写绝对路径换台机器就失效）
  → 当前工程目录的**父目录** → 图层所在目录的**父目录**
  → 上次打开的工程目录 → 桌面。
  ⚠ 必须是**父目录**：对话框返回值会再拼工程名，给"目录自己"会白套一层
  （`…\1516601\1516601`）。
  🔴 **「默认工作路径」只作对话框初值，绝不参与落点决策** —— 这是硬约束。
  历史上叫 `DefaultSavePath` 的设置项正是因为被 `btnParamSetting_Click` 拿去顶替
  `_currentTemplatePath`，才让"打开工程 A → 改个颜色 → 点确定 → 再保存"把内容写去别处
  （见 `MD文件汇总（AI）/问题&解决方案/参数设置确定按钮改写工程归属.md`）。
- 🆕 **新建工程 = 先问名字 → 选文件 → 载入完自动落盘**：载入完成时工程已经在磁盘上，
  不需要用户再点一次「保存」。落点优先取「默认工作路径 \ 工程名」，不可用时才当场问。
  「另存到」同样可以改名 —— 它就是"给工程改名"的正规入口。
- 🆕 **支持拖放**：拖 Gerber 文件进窗口 —— 有工程时**追加图层**（保留归属 / 选点 / 当前视图），
  没有工程时等同新建；与已有图层**同名**会弹窗询问是否替换（替换会清掉该层选点）。
- **文件写入走 `WriteFileAtomic`**，别退回 `WriteAllText`。
- 🆕 **命中排序是四级**：① 图层叠放（大者胜）→ ② 命中内部优先于"只是落在容差里" →
  ③ 都在内部时**尺寸小者胜**（否则圆内部的 `len − r` 会让大圆通吃）→ ④ 都在容差内时距离近者胜。
  最上层该处没图形则**穿透**到下一层。
  ⚠ 第 ③ 档是**单图层场景下的唯一防线**（那时 layerDepth 全体相同，①②两档直接失效）。
- 🆕 **图层状态一律拷进图形对象**（`LayerId` / `LayerDepth` / `LayerHidden`），
  **绝不用"图层名"做字符串匹配** —— 匹配一旦失败会**静默退化**成纯距离排序，且无报错可查。
  🔴 **必须在 `BuildAllShapes()` 之前调 `EnsureLayerIdentity()` 把图层 Id 分配好**：
  图形的 `LayerId` 取自 `LayerInfo.Id`（初值 0），Id 没分配就写进去 → 全体 `LayerDepth` 变成 −1
  → "叠放优先"整档静默失效（表现：**置顶了也选不到那一层**）。
  构建日志里有自检「⚠ 有 N 个图形没有图层身份」，正常应为 0。
- 🆕 **隐藏图层 = 不画 + 不选 + 数据保留**：绘制 2 处 + 命中 + 框选 + 多选扩散共四处过滤，
  统一走 `IsShapeLayerVisible()`。
- 🆕 **图形的唯一键是四维的**（图层 + 坐标(4 位小数) + 形状 + **尺寸**），三处使用点必须口径一致。
- 🆕 **图层容器的首行是表头**（`文件名` ｜ `置顶` ｜ `【全选】`），它与图层行**共用同一份列几何**
  `LayerRowLayout` —— 列位置只写一处，否则表头会与内容错开一格（且只能靠肉眼发现）。
- 🆕 **批量显隐走"重建容器"、单行切换只"刷新"**：每行的复选框是该行控件的私有字段，
  全选（`SetAllLayersVisible`）必须重建才能让所有方框同步；单行（`OnLayerRowVisibilityChanged`）
  自身已是最新，重建反而会清掉悬停态。
- 🆕 **选点按插针头类型划分**（`SelectedCircle.HeaderType` = `h1`/`h2`/`h3`，v2.4 新增，与 `Layer` **正交**）：
  工具栏三个互斥 toggle 决定"接下来选中的点归哪个头"，**切头类型不改动已选点**
  （要改就在目标头下重新点它，或用框选重新框进来 —— 框选可用 Ctrl+Z 把类型一起撤销）。
  三个头的颜色**都能在「参数设置」里改**（`h1 颜色` / `h2 颜色` / `h3 颜色` 三行）：
  默认 h1 = 设置项 `SelectedCircleColor`（白）、h2 = `HeaderH2Color`（黄）、h3 = `HeaderH3Color`（绿）。
  h1 的默认值保持白 —— 于是老工程（`Header` 缺失 → 全部读成 h1）打开后的观感与改动前一模一样。
- 🆕 **合并生成的点必须在图形缓存里**：它的坐标是两点中点，**不落在任何 Gerber 光圈上**，
  靠 `AppendOrphanSelections()` 收编进 `_allShapes` —— 否则就是"画得出来、存得下去、却点不中"的幽灵点
  （V5 里正是这个状态）。收编时沿用生成它的图形的 `LayerId`，图层深度 / 隐藏状态因此与同层图形一致。
