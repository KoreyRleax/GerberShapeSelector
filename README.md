# GerberParserSmartV4.0

Gerber 选点工具。工作流：

```
打开/新建工程（= 一个目录，内含若干 Gerber 图层） → 在图上挑出需要的焊盘/针位 → 保存成 circles.json
```

使用者时间几乎全花在"挑点"上，所以复杂度集中在选点交互，不在解析或渲染。

---

## 一、数据模型（本次裁定）

### 1.1 一句话模型

> **工程 = 一个目录 = N 个 Gerber 图层文件 + （可选）一个 `circles.json`**

`circles.json` 存在 → 这个工程有选点；不存在 → 新工程，选点为空。
**"模板"不再是一个独立概念**，它就是"有 circles.json 的工程"。

这样裁定的理由（三条）：

1. **模板和 Gerber 不是两种东西，是同一工作区的两种状态**（有 / 无选点元数据）。
   把它们做成两个按钮、两条加载路径、两套保存规则，等于把"状态"误建模成"类型"——
   代价是让用户去猜程序内部的分类。
2. **多图层让这个裁定的必要性变成硬性的**：一个目录里躺着一堆 `.GBL/.GBS`，
   再单独区分"我在打开 Gerber 还是在打开模板"已经没有意义了。
3. **用户的心智里只有一个动作**："打开这块板子的工作目录。"

### 1.2 对象图

```
Project（工程）
├─ RootPath      string                 工程根目录（绝对路径）
├─ Layers        List<Layer>            图层，有序；顺序 = 显示顺序（后加入的在上）
│   └─ Layer
│       ├─ FilePath   string            图层文件全路径
│       ├─ FileName   string            显示名，如 1516601-00-C_01.GBL
│       ├─ IsVisible  bool              图层容器复选框；默认 true
│       └─ Apertures  List<Aperture>    该图层解析出的光圈（含全部位置）
├─ CirclesPath   string                 RootPath\circles.json（可能不存在）
└─ Selected      List<SelectedCircle>   选点集合，跨图层，带 LayerIndex
```

**图层是全模型的一等公民。** 现有代码里 `_apertures` 是"一个平铺的光圈列表"、
`SelectedCircle` 是"一个平铺的图形" —— 多图层后它们都必须挂上图层归属，否则：

- 两个图层在同一坐标有同形状图形时，会被去重索引 `(X, Y, Shape)` 当成同一个；
- 命中测试、框选、图层显隐都会算错。

**因此图形的唯一键从 `(X, Y, Shape)` 升级为 `(LayerIndex, X, Y, Shape)`。**
这是本次改造对现有代码影响最广的一处，务必先改这里。

### 1.3 四条硬规则

| # | 规则 | 说明 |
|---|---|---|
| **R1** | **只有真正打开了 Circle 图层，选点才生效** | 导出时只导出"图层可见且在图上选中的点"。取消勾选某个图层 = 该图层的图形不参与显示与选点 |
| **R2** | **同位置多图形默认联动选中** | 见 1.4 |
| **R3** | **无法解析的文件：跳过，且不在图层容器中显示** | 见 1.5 |
| **R4** | **所有能打开的工程都可修改** | 打开即进入可编辑态；保存写回 `RootPath`。没有"只读预览"这种模式 |

### 1.4 R2：同位置多图形（GBL / GBS 大量坐标相同、仅尺寸不同）

背景：`.GBL`（底层）和 `.GBS`（丝印/阻焊）经常在同一坐标放着不同尺寸的图形。
用户点一个位置时，真正要决定的是"**这个位置要不要**"，而不是"这个位置的哪个图形要"。

**裁定分两层：**

**交互层 —— 默认联动。** 同一坐标（容差内）的所有图形视为一个"位置组"：
点中即整组选中 / 整组取消。这让用户的心智保持为"位置级"，不用去分辨 0.508 和 1.75 的差别。

保留一个逃生门：右键菜单提供「仅选中此图形」，给"确实只要其中一个"的场景用。

**保存层 —— 必须去重。** `circles.json` 是给插针机上位机读的，
**同一个坐标出现两次 = 插两次针**，属交付缺陷。所以导出前对选点按坐标做一次去重，
冲突时保留一个（建议保留**尺寸最大**的那个，即最外层/最确定的焊盘），
并在导出报告里说明"消除了 N 个重复坐标"。具体保留策略见 1.6 待确认项。

### 1.5 R3：无法解析的文件

判据：`GerberParser.DetectFileType()` 无法识别，或解析后光圈/图形数为 0。

处理：**跳过 + 不进图层容器 + 导入完成后汇总提示一次**
（"3 个文件无法解析，已跳过：a.xxx、b.xxx、c.xxx"），不要逐文件弹框。

> ⚠ 现有 `ParseFile()` 在 `DetectFileType()` 返回 false 时**仍会硬按 Gerber 解析**
> （`GerberParser.cs:244-249`）。多图层下这会让丝印、宏定义等文件产生垃圾图形进入画布，
> 必须在 dll 侧改成"返回可判定的失败"。

### 1.6 circles.json 格式演进

现状（v2.0，实测自 `bin\x64\Debug\Json\GBL1\circles.json`）：

```json
{
  "TemplateInfo": {
    "TemplateName": "GBL1",
    "SourceFile": "1516601-00-C_01.GBL",   // ← 单数！多图层下不够用
    "TotalCount": 32, "SelectedCount": 32,
    "CircleCount": 27, "RectangleCount": 5, "OvalCount": 0,
    "SaveTime": "2025-11-17 14:30:19",
    "Version": "2.0",
    "MirrorState": { "IsMirroredX": false, "IsMirroredY": false }
  },
  "Shapes": {
    "Circles":    [ { "Id": "272", "SizeX": 7.7, "SizeY": 7.7, "Positions": [ { "X": 64.4, "Y": 42.15 } ] } ],
    "Rectangles": [ { "Id": "..", "Type": 1, "SizeX": .., "SizeY": .., "Positions": [ .. ] } ],
    "Ovals":      [ { "Id": "..", "Type": 2, "SizeX": .., "SizeY": .., "Rotation": .., "Positions": [ .. ] } ]
  }
}
```

**v2.1 需要新增（全部为可选字段，不破坏旧读取方）：**

| 新增 | 位置 | 用途 |
|---|---|---|
| `Layers` | `TemplateInfo` | 图层清单：`[{ "FileName": "...GBL", "IsVisible": true }, ...]`。导入工程时据此重建图层容器与勾选状态 |
| `Layer` | 各 shape 条目 | 该点所属图层（文件名或序号），可选。缺失时按"唯一图层"处理 |
| `DuplicateCount` | `TemplateInfo` | 本次导出消除掉的重复坐标数，便于追溯 |

**两条必须遵守的兼容约定：**

- **`Positions` 是数组**，但现有读取端只取 `Positions[0]`（`MainForm.cs:2227/2247/2266`）。
  若要支持"一个 shape 带多个位置"，**必须同时改读取端**，否则静默丢点。
- 读取端走 `dynamic`，**字段拼错要到运行时才报错**（交接文档已列为遗留项）。加字段时优先保持一致风格，避免半路换强类型引入不一致。

### 1.7 三个工程操作

| 操作 | 入口 | 行为 |
|---|---|---|
| **新建工程** | 菜单「文件 → 新建工程」 | 多选 Gerber 文件 → 逐个解析 → **无法解析的跳过并汇总提示** → 图层容器列出全部图层、**初始全部勾选** |
| **导入工程** | 菜单「文件 → 打开工程」 | 选一个含 `circles.json` 的工程目录 → 加载全部图层 + 恢复选点 + 恢复图层勾选状态 → **可编辑** |
| **删除工程** | 菜单「文件 → 删除工程」 | **仅从工作区移除**（清空图层/选点/视图），不删磁盘文件；二次确认。语义见 1.6 待确认项 |

## 三、技术栈裁定：留在 WinForms

明确不考虑迁移到 WPF。理由：

- 本次要做的改动（顶部菜单、状态栏、删面板、右上角悬浮容器）**没有一样是 WinForms 做不到的**，
  难度都不高；
- 迁移成本全部落在**与需求无关**的地方：XAML 重写、`OpenFileDialog`/`FolderBrowserDialog`/`MessageBox` 全换、
  `RectangleF`→`Rect`、`MouseButtons`→`MouseButton` 逐处适配；
- 最贵的一条：画布层要从 `Korey.SmartWindow.WinForms` 换成同一个库的 WPF 分支。
  虽然 API 逐字一致，但 WPF 版**未在 15,359 图形、框选、旋转椭圆命中测试这些场景验证过** ——
  而这正是本工程的价值所在。用未验证的核心换已验证的边缘，风险不对称；
- DPI 感知这个遗留问题**不需要 WPF 解决**：.NET Framework 4.8 支持在 `App.config` 里声明
  Per-Monitor V2，"高清版"在缩放显示器上被位图拉伸的问题即可消除。

**什么时候该重新考虑**：`Korey.SmartWindow.Wpf` 被独立验证过（有 demo 跑满 15k 图形）、
或界面开始出现大量数据绑定需求（图层属性表格、选点列表）。到那时，画布层 API 的逐字一致
保证了迁移不会太痛 —— 所以**推迟没有代价**。

## 四、构建与依赖

```
用 VS 打开 GerberParserSmartV4.0.sln，选 Debug|x64 或 Debug|AnyCPU，F5

命令行等价：dotnet build GerberParserSmartV4.0.csproj -c Debug
（本沙盒实测可用：VS2022 提供 v4.8 targeting pack，dotnet build 走托管版 MSBuild，
 不受"MSBuild.exe 被判定为受限二进制"的影响；约 1.8 秒）
```

| 依赖 | 来源 | 说明 |
|---|---|---|
| `Korey.SmartWindow.WinForms` | `lib\Korey.SmartWindow.WinForms.dll` | 自研画布控件库，源码在 `D:\MyWork\Common`，API 契约见 `Korey.SmartWindow.API.md` |
| `GerberParserTool` | 源码在 `D:\CSharpWorkBase\ClassLib\GerberParserTool\`（net48 类库） | Gerber/钻孔解析器。**源码没丢**，改动后需把 dll 拷回本工程 `bin\Debug\` 与 `lib\` |
| `Newtonsoft.Json` | `packages\Newtonsoft.Json.13.0.4\` | circles.json 读写 |

### 雷区

- ⚠ **`bin\x64\Debug\Json\` 是真实使用者的工程数据，不可再生。** 清理 `bin`、重编、改输出路径前必须确认它安全。
- `GerberParserTool` 的引用指向 `bin\Debug\`（本工程自己的输出目录），清空 `bin` 后再编译会失败；建议挪进 `lib\`。
- 源码是 **UTF-8 带 BOM + CRLF**，批量改文件必须保持，改成 LF 会让 diff 爆炸。
- `LangVersion` 只在 x64 配置里显式声明为 7.3；AnyCPU 走编译器默认值。
- 日志：`KLog` → exe 目录下 `logs\yyyy-MM-dd.log`，排查问题先看它。
- `Program.FileName` 是隐式全局状态，默认值为原开发者本机绝对路径（换机失效）。

### 关键设计决策（改前必读）

- **选点不要门禁**：左键任何时候都能选点，单选/多选只是"点击语义"，不是开关。
- **框选 = 选择；框选限定 = 作用域**：限定只影响多选时"同类扩散"的范围，**不拦截点击命中**。
- **框外点击一律解除限定**（单选/多选/右键共用 `ReleaseScopeIfOutside`），规则只能有一条。
- **`IsSelected` 与 `_selectedCircles` 是两份状态，必须同步**；清空一律走 `ClearAllSelection()`。
- **画布背景纯黑**，光圈配色按"对纯黑对比度 ≥ 4.5:1"筛选。
- **`Color.Green` ≠ Halcon `green`**：本工程语义是 (0,255,0)，颜色转换两头都要对齐。
- **保存是就地保存**，落点必须对用户可见（显示完整路径）。
- **文件写入走 `WriteFileAtomic`**，别退回 `WriteAllText`。

详见 `GerberParserV4.0_交接文档.html`（代码地图、数据流、9 条设计决策与踩过的坑）。

## 五、业务规则裁定

| # | 事项 | 裁定 | 实现要求 |
|---|---|---|---|
| 1 | 同坐标多图形去重时保留哪个 | **保留尺寸最小的** | 导出前按坐标去重；冲突时比较尺寸，保留**最小**者；`TemplateInfo.DuplicateCount` 记录被消除的数量 |
| 2 | 「删除工程」的边界 | **连磁盘目录一起删** | ⚠ 破坏性操作。实现约束：① 先扫描并**列出将被删除的全部文件**给用户看；② 二次强确认，默认按钮为"否"；③ 删除走**回收站**（`SHFileOperation`/`Microsoft.VisualBasic.FileIO`），**不用永久删除**；④ 若目录里没有 `circles.json` 也没有可识别的 Gerber 文件，拒绝执行并提示 |
| 3 | 图层取消勾选时已选点的显示 | **点也一起隐藏** | 可见性同时作用于该图层的图形与已选点；**但不改变** `Selected` 集合，也不影响导出结果 |
