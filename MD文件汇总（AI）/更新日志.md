### 17. 状态栏缩放单位澄清 + 修掉悬浮浮层的闪烁

- **① 状态栏文案**：`缩放 150.000×` → **`缩放 150.000 px/单位`**。
  原来的 `×` 容易被读成"倍数"，而 `Scale` 实际是「世界单位 → 屏幕像素」的比例（`1.0` = 1:1）。
- **② 浮层下方图形闪烁**（用户报）：顶部工具栏与右上角图层容器**覆盖的那块区域**里的图形会闪。
  两条原因（都在控件库侧，修都在本工程侧）：
  - 🔴 **主因：视口变化时浮层压根没被重绘。** `KWindowControl.OnViewportChanged`（`:233-238`）
    用的是 `Invalidate()`（**无参 = 不失效子控件**），而浮层**正是子控件** →
    滚轮 / 平移时浮层停在**缩放前的旧画面**上，直到别的原因才重绘。
    修：本工程 `OnViewChanged`（`MainForm.cs:774`，原本只刷状态栏）补一句 `Invalidate(true)`。
  - **次因：浮层没有双缓冲。** 浮层是半透明的 —— 重绘时要先让父控件补画底下内容、再叠半透明底
    （`OverlayToolbar.cs:14-22` 的"透明链"）；而画布有 `OptimizedDoubleBuffer`（`:116`）、
    浮层只有 `SupportsTransparentBackColor`（`:57`）→ 那两步直接画屏幕，会露中间态。
    修：本工程侧新增 `DoubleBufferedOverlayToolbar : OverlayToolbar`（一行 `DoubleBuffered = true;`），
    两处 `new OverlayToolbar()` 换成它。
  **两处都没动共享控件库** `Korey.SmartWindow`。
- **③ 顺带**：`RefreshKWindow()` 的 `Refresh()`（= `Invalidate(true)` + `Update()`，**同步**画完才返回）
  → `Invalidate(true)`（异步标脏、仍失效子控件）。影响的是"**数据变化后的刷新**"
  （选点 / 切图层 / 清空等 25 个调用点），**不是滚轮** —— 滚轮走控件内建的 `Invalidate()`，本来就异步。
- **详见**：`MD文件汇总（AI）/问题&解决方案/悬浮浮层下方图形闪烁.md`

### 16. 视图缩放上限做成配置项（App.config）

- **起因**：用户问"为什么 `Broad\q02578f045a00` 默认缩放是 150x？最大只能到 500，能不能给个配置文件改到 1000"。
- **先解释两件事**：
  - **默认缩放不是固定值**，是 `FitToWindow` 按内容包围盒算的：
    `scale = min(可用宽/内容宽, 可用高/内容高) × FitMarginRatio(0.9)`。
    那块板**只有 8.7 × 5.2**（世界单位 mm），却要铺满整个画布 → 每单位要占 120~150 个像素。
    实测（1200×800 画布）得 `scale = 124.0`；用户窗口更大（约 1600×900）所以是 ~150。
  - ⚠ **`Scale` 的语义是"世界单位 → 屏幕像素"的比例（`1.0` = 1:1），不是"倍数"**。
    状态栏 `缩放 150.000×` 里那个 `×` 只是装饰 —— 实际是 1 个世界单位（mm）占 150 个像素。
- **改了什么**：`App.config` 新增 `<appSettings>` → `<add key="ViewMaxScale" value="500" />`；
  `MainForm.ApplyViewScaleLimits()` 在 `MainForm_Load` 里读它并设 `kWindowControl1.Viewport.MaxScale`。
  缺失 / 非数字 / ≤0 / NaN 一律**忽略**（保持控件库默认）—— 不会因为写错一个值把上限设成 0。
- **顺带修的**：csproj 补 `<Reference Include="System.Configuration" />`。项目原本没有它 ——
  `Settings.Designer.cs` 用的 `ApplicationSettingsBase` 在 **System.dll** 里，而
  `ConfigurationManager` 在 **System.Configuration.dll**，所以这个缺失直到本次才暴露。
- **改哪一份**：要**持久生效**就改**源码的 `App.config`**（编译时生成 exe 旁的 `exe.config`）；
  直接改 exe 旁的 `exe.config` 只对当前这份 exe 有效、**下次编译会被覆盖**。改完需**重启程序**。
- ✅ 编译 0 warning / 0 error；生成的 `GerberParserSmartV4.0.exe.config` 里已确认含该配置项。

### 14. 缩放卡顿：绘制精度按屏幕尺寸分级（LOD）

- **问题**：几万图元时，缩到整板视图卡顿。实测（真实板 8 图层 / **20188 图元** /
  221×133 mm，默认视图 scale 4.88 px/mm）：底图逐个**精确描边** ≈ **56 ms/帧（约 18 fps）**，
  其中 **3~5px 那一档（15660 个，77.6%）独占约 32 ms（57%）**。
- 🔴 **一个反直觉的实测事实**：这块板上的图元**最小也有 2.2 px**（PCB 工艺尺寸下限：
  焊盘/过孔/线宽 ≥0.2~0.3mm），**<2px 的图元是 0 个** —— 所以"把亚像素图形跳过"这条路
  在这类板上**省不了任何东西**。真正有效的是**降低单个图形的绘制成本**。
- **改了什么**：底图按**每个图形自己的屏幕尺寸**分档 —— `<1px` 不画、
  `1~5px` 画成"**边长等于自身外接框的实心方块**"（尺寸不变，只抹掉圆/椭圆的形状细节）、
  `≥5px` 走精确绘制。判据用屏幕尺寸而非缩放级别，所以**放大后自动恢复精确**，无切档跳变。
  只作用于底图，选点永远精确绘制。
- **效果**（同口径离屏 GDI+ 实测）：**56 ms/帧 → 16.5 ms/帧（0.30x）**。
- **实测否掉的做法**：把 20000 个椭圆合并成一条 `GraphicsPath` 再画 → 反而慢 **3.5 倍**。
- **落点**：`MainForm.cs` 的 `DrawGerberApertures`（每图层分两趟画）+ `LodTierOf` /
  `LodSkipPx` / `LodBlockPx`（阈值集中，改一处即可）。
- **详见**：`MD文件汇总（AI）/问题&解决方案/缩放卡顿与绘制精度分级.md`

### 13. 保存前拦下「同坐标重复点」
