## 2026-09-21

### 1. circles.json 升级到 v2.5 —— 坐标扁平化

- **改了什么**：图形记录的坐标从 `"Positions": [ { "X":…, "Y":… } ]` 数组里提出来，
  直接写成 `"X":…, "Y":…`。一个记录本来就只放一个坐标，那层数组是纯粹的历史包袱，
  还逼着下游解析多写一层循环。
- 🔴 **读端不兼容旧格式**（用户裁定）：打开 v2.0~2.4 的老工程，坐标会**全部读成 0**、点堆在原点。
  ⚠ 打开这类老工程后**别点保存**，否则会把"全 0"写回去，**不可逆**。
- **落点**：`MainForm.cs` 写端三条 `Shapes.*[]` 记录 + `Version` → `2.5`；读端新增 `ReadJsonPosition`。
- **详见**：`MD文件汇总（AI）/系统架构&协议设计/数据格式-circles.json.md`

### 2. 下游插针机（RivetPin2019）对齐本项目格式

- **改了什么**：插针机 `Common\CADImportDlg.cpp` 原按**老项目 V5** 的
  `Shapes = { h1:{Circles,…} }` 解析，喂本项目 json 会崩在 `json_value.cpp`
  （jsoncpp 前置断言 + 无人 catch）。现改为只认本项目的 `Shapes = { Circles / Rectangles / Ovals }`，
  头类型读每条记录的 `Header`。
- **不做 V5 兼容**（用户裁定：V5 后续将废弃）；同时补了**逐元素判类型**与**外层 try/catch** ——
  这两条与格式无关，是 jsoncpp 的 `isMember` / `operator[]` / `asCString` 都带前置断言，
  产线程序不能因一份畸形文件就崩。
- ⚠ 插针机代码不在本机工程里，**未编译**，需在产线工程编译后实机验证。
- **详见**：`MD文件汇总（AI）/问题&解决方案/插针机导入json崩溃（Shapes顶层按形状分组）.md`

### 3. 工程管理：保存时可自定义工程名

- **问题**：新建工程后首次保存，工程名是**推**出来的（第一个 Gerber 文件**所在目录**的名字），
  只让选上级目录、名字由程序拼上 —— 素材目录叫 `1516601-00-C`，工程就只能叫 `1516601-00-C`。
- **改了什么**：新增「保存工程」对话框（`SaveProjectDialog.cs`），一次问清**工程名 + 保存位置**，
  底部实时显示完整落点。「另存到」复用同一个对话框 —— 于是**改工程名**有了正规入口：
  另存到同一父目录 + 改个名。
- **落点规则一个字没改**：有归属仍是就地保存；对话框只在「新建后首次保存」与「另存到」出现。
- **详见**：`MD文件汇总（AI）/任务&需求/R-20260921-05-工程管理与拖放加载.md`

### 4. 拖放加载：把 Gerber 文件拖进窗口

- **没有工程时**：拖文件 = 新建工程（等价「文件 → 新建工程」）。
- **已有工程时**：拖文件 = **追加一个图层**。新图层加在末尾（= 压在最上层），
  保留当前工程的归属、选点与视图（**不重置视图** —— 你正盯着某处看，不该被甩走）。
- **同名文件**：弹窗询问是否替换；替换会**清掉该图层上的选点**
  （图形已整批换新，旧选点留着就是"点不中的幽灵点"），连框选撤销栈里的相关快照一并剔除。
- **拖到哪都行**：画布、工具栏、状态栏、路径栏都生效；拖入文件夹会提示改用「打开工程」。
- **详见**：`MD文件汇总（AI）/任务&需求/R-20260921-05-工程管理与拖放加载.md`

### 5. 新增「默认工作路径」设置项

- **问题**：各工程目录一般都放在同一个地方，但「打开工程」的对话框每次停在**上次那个工程目录**里，
  于是每次都要往回退一层再进另一个目录。
- **改了什么**：`参数设置` 新增一行「默认工作路径」（可手输、可浏览选择），
  设置后「打开工程 / 另存到 / 首次保存」的对话框都从那儿出发。
- **开箱即有默认值**：`程序目录\Broad`（即 exe 旁边的 `Broad` 文件夹，首次启动自动创建），
  不必先手动设一遍。默认值在设置项里存的是**相对路径** `Broad` ——
  写绝对路径的话换台机器就指向不存在的地方（`Program.FileName` 当年正是这个毛病）。
  解析规则：空 → 程序目录\Broad；相对路径 → 拼程序目录；绝对路径 → 原样用（不存在则回退到 Broad）。
- 🔴 **与已删除的 DefaultSavePath 的关键区别**：那个设置项当年**越界**了 ——
  它被 `btnParamSetting_Click` 拿去顶替 `_currentTemplatePath`，于是"打开工程 A → 改个颜色 →
  点确定 → 再保存"会把内容写去别处。新项**只做对话框初值，绝不参与落点决策**
  （落点仍只有两个来源：有归属就地写回 / 无归属当场问）。
- **详见**：`MD文件汇总（AI）/问题&解决方案/参数设置确定按钮改写工程归属.md`（旧缺陷）+ 本文第 5 条

### 6. 选点按插针头类型划分（h1 / h2 / h3）+ 合并

### 9. 多图层选点三处修复

| 症状 | 根因 | 修法 |
|---|---|---|
| 怎么点都只能选到最大圆圈那层 | 命中排序只比"到边界距离"，而圆内距离 = `len - r` → 半径越大越"近" | 改成**先比图层叠放、同层内再比距离**；最上层该处没图形则穿透到下一层 |
| 隐藏图层的选点还画着、还能点中 | 绘制（底图与选点是两条路径）、命中、框选、多选扩散**四处**漏了显隐过滤 | 统一走 `IsShapeLayerVisible()`，四处都接上；**数据不删**（重新勾上图层，选点原样回来） |
| 某些点"怎么都点不中" | 图形唯一键少了**尺寸**这一维 → 同层同坐标的焊盘与它的外形框互相顶替 | 唯一键补成四维（图层 + 坐标 + 形状 + **尺寸**） |

- **详见**：`MD文件汇总（AI）/问题&解决方案/选点只能选到最大圆圈那一层.md`、`隐藏图层的选点仍然可见可点.md`、
  `重复坐标的图形互相顶替.md`

### 10. 新建工程：先定名字 → 选文件 → 载入完自动落盘

- 流程改成：**先问工程名 → 再选 Gerber 文件 → 载入完自动保存**，不用再回主界面点一次「保存」。
- 落点优先取「默认工作路径 \ 工程名」；没设默认路径、或那儿已有同名目录时，才弹一次让你选位置。
- 拖放新建同理（文件已经拖进来了，所以先载入、成功了再问名字 —— 免得输完名字才发现文件都解析不了）。

### 11. 命中排序的两个修复（症状都是"总是选中大圆"）

| 症状 | 根因 | 修法 |
|---|---|---|
| **只有一个图层**时也总是选中最大那个圆 | 同层内只有"边界距离"这一档，而圆内部 `d = len − r`（半径越大越负）→ 大圆通吃 | 同层内改为**命中内部者优先、都在内部时尺寸小者胜** |
| **置顶了小圆图层，还是选到大圆图层** | `FinishProjectLoad` 里 `BuildAllShapes()` 早于图层 Id 分配 → 图形的 `LayerId` 全被写成 0 → `LayerDepth` 全是 −1 → "叠放优先"这一档**静默失效** | 把 Id 分配抽成 `EnsureLayerIdentity()`，在 `BuildAllShapes()` **之前**调用；并加了一条自检日志 |

- 第二个只在"载入后没有第二次 `BuildAllShapes`"的路径上暴露：打开**存过选点**的工程会因恢复选点再跑一次而侥幸正常，**新建工程必然中招**。
- **详见**：`MD文件汇总（AI）/问题&解决方案/选点只能选到最大圆圈那一层.md`（§5.4 / §5.5）

### 13. 保存前拦下「同坐标重复点」

- **问题**：插针机按**坐标**定位打针（不读 `Layer`），而本项目允许多图层上的点落在同一坐标 ——
  于是同一个位置会被插两次针。重复从三条路径产生（**框选**、隐藏上层后选下层再恢复、合并/游离点落点），
  而保存端落盘前**零查重**。
- **改了什么**：用户裁定"**这种情况不被允许**"，实现为**保存前检出 + 弹窗**：
  列出每处冲突的「坐标 / 图层 / 形状尺寸 / 头类型 / 是否隐藏 / 是否选中」，
  由用户选「返回修改」（**一个文件都不写**）或「仍然保存」（记日志）。
- **刻意不做的事**：不自动去重（"保留哪一条"是业务判断，猜反就是打错针位）、不改选点行为
  （选点仍不设门禁）、**不动图形的四维唯一键**（那是另一套口径）。
- **落点**：新增 `DuplicatePositionDialog.cs`；`MainForm.cs` 新增判重/明细/确认 4 个方法，
  调用点在 `SaveTemplateToPath` 开头（在"是否覆盖"确认之前）。
- **详见**：`MD文件汇总（AI）/任务&需求/R-20260921-06-保存前同坐标重复点检查.md`

### 12. 打开工程快 150 ms

- `ApplyLayerVisibility` 用 `try/catch` 探测"v2.3 才有的字段"，打开老工程时每个图层抛一次
  `RuntimeBinderException`，6 个图层 = 150 ms。改用 `JToken` 索引器（取不到返回 null，不抛异常）。
- **详见**：`MD文件汇总（AI）/问题&解决方案/打开工程慢150毫秒（用异常探测字段）.md`
