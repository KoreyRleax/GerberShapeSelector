# 系统架构&协议设计 · 说明与规范

> **这部分基本确定后就不用动**。它是"当前事实"的快照，不是改动记录。
> 与 `.workbuddy/memory/` 的区别：那边是过程（谁在什么时候改了什么），这里是**结论**（现在是怎么运作的）。

## 包含什么

| 文件 | 内容 |
|---|---|
| `系统架构总览.md` | 程序角色、代码地图、数据流、分层与职责边界、关键不变量 |
| `数据格式-circles.json.md` | 模板文件结构、版本演进、图形唯一键口径、与下游的契约 |

## 写作要求（重要）

1. **以代码为准**。参考素材（`.workbuddy/memory/`、交接文档、README）**不一定是最新的**；
   有疑问直接查代码。
2. **关键结论必须标来源**：`（来源：文件:行号）`。
3. **无法核实的一律标 `⚠️待核实：<原因>`，禁止臆造**字段名、超时值、接口行为。
4. 每份文档头写：适用范围 / "以代码为准"的声明 / **最后核对日期** / "AI 整理，需人工复核"。
5. 改了数据结构、文件名、字段 → **同步更新这里**并改核对日期。

## 本工程没有"协议"类文档

本程序是**离线桌面工具**（读 Gerber → 挑点 → 存模板），不与下位机、也不与视觉软件通信，
因此没有"上位机↔下位机""VM↔上位机"这类协议文档。
**与下游的契约就是 `circles.json` 的结构** —— 那份契约写在 `数据格式-circles.json.md` 里。
