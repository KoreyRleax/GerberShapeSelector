## 一、这是什么

一个 **Gerber 选点工具**的桌面程序（WinForms / .NET Framework 4.8）。工作流：

```
打开工程（若干 Gerber 图层叠起来看）  →  在图上挑出需要的焊盘 / 针位  →  存成「模板」
```

模板 = 一个目录 = `circles.json`（选中的点）+ 全部图层文件拷贝，供下游设备按模板定位。
**使用者的时间几乎全花在"挑点"上**，所以复杂度集中在选点交互，而不是解析或渲染。

## 四、数据流

```
Gerber / 钻孔文件（一个文件 = 一个图层）
   │  GerberParser.ParseFile()            ← 每个文件一个实例解析；ParseFile 开头 Reset() 清空光圈字典
   ▼
List<Aperture>（每个 Aperture：形状 + 尺寸 + 该层上的全部位置）   ← Aperture.Layer 由 GerberParser.LayerName 回填
   │  LayerInfo 持有它；_apertures = 所有图层的扁平聚合（RebuildAperturesFromLayers）
   ▼
BuildAllShapes()                          ← 只在载入工程后跑一次
   ▼
_allShapes : List<SelectedCircle>（扁平成一个个可点的图形；带 LayerId / LayerDepth / LayerHidden）
   │  UpdateContentBounds()
   ▼
_contentBounds（算一次，绘制 / 视图适配复用）

交互只改两处：SelectedCircle.IsSelected 与 _selectedCircles（见"关键不变量"第 1 条）

_selectedCircles
   │  SaveTemplateToPath()
   ▼
模板目录\circles.json  +  全部图层文件拷贝
```

## 五、图层模型（本程序最复杂的一块）

- **一个图层 = 一个 Gerber / 钻孔文件**。`_layers` 是权威数据（来源：`MainForm.cs:24` 附近的注释）。
- **顺序即真相**：`_layers` 的**末位 = 最后绘制 = 压在最上面 = 命中优先**（来源：`DrawGerberApertures` 的绘制循环）。
  用户可以点图层行里的「↑」图标把某层移到末位（`MoveLayerToTop`，来源：`MainForm.cs:2910`）。
- **容器倒序显示**：图层容器第一行 = `_layers` 末位 = 画面最上层（来源：`RefreshLayerPanel`，`MainForm.cs:695`）。
- **容器首行是表头行**：`文件名` | `置顶` | `【全选】`（2026-09-21 起，来源：`LayerHeaderControl`）。
  它与图层行**共用同一份列几何** `LayerRowLayout`（列位置只写一处，避免表头与内容错开一格）；
  `置顶` 列宽是**量出来的**（`max(24, 「置顶」文字宽 + 6)`）而不是写死的 24。
  表头只有方框可点（全选 / 取消全选，三态显示）；改的仍是 `LayerInfo.IsVisible`，不碰选点数据。
- **批量显隐走"重建容器"、单行切换只"刷新"**：每行的复选框是该行控件的私有字段，
  全选改了所有图层就必须重建才能同步（`SetAllLayersVisible` → `RefreshLayerPanel`）；
  单行被点的那一行自身已是最新，重建反而会清掉悬停态（`OnLayerRowVisibilityChanged`）。
- **图层身份用 `LayerInfo.Id`**（会话内唯一、置顶重排不变）；
  **配色用 `LayerInfo.ColorIndex`**（载入时定下、不随重排变）——
  两者都**不能用"当前序号"**（序号会被置顶改变）。
- **图形的图层状态是"拷贝"不是"引用"**：`SelectedCircle` 带 `LayerId` / `LayerDepth` / `LayerHidden`
  三个运行期字段，由 `RefreshLayerState()`（`MainForm.cs:3582`）在
  "载入工程 / 勾选显隐 / 图层置顶"三处刷新。**这是刻意的**，理由见关键不变量第 4 条。
- **选点还带一个"插针头类型"**：`SelectedCircle.HeaderType` = `h1` / `h2` / `h3`（默认 h1，v2.4 进 json）。
  它与图层**正交** —— 同一图层上的点可以分属三个头，同一个头的点也可以散布在多个图层上；
  只影响**配色**（h1 = 参数设置里那个色，h2/h3 = 固定黄/绿）与导出分组，**不参与任何几何判定**。
  工具栏三个互斥 toggle 决定"接下来选中的点归哪个头"；**切换不改动已选点**。
- **不在任何 Gerber 图形上的选点**（合并生成的中点、坐标对不上的老 json 选点）由
  `AppendOrphanSelections()` 收编进 `_allShapes` —— 否则它们"画得出来、保存得下去、却点不中"。
  收编时沿用生成它的图形的 `LayerId`，因此图层深度 / 隐藏状态与同层图形一致。

## 六、两条绘制路径 + 三个选取入口（改代码前必读）

这个工程里，"图层显隐"和"能不能选中"各有多条独立路径，**改一处不够**：

**绘制（两条独立路径）**

| 路径 | 画什么 | 显隐过滤 |
|---|---|---|
| `DrawGerberApertures` | 底图（全部图层的 Gerber 光圈轮廓） | 读 `layer.IsVisible` |
| `DrawSelectedCircles`（Gerber 模式）/ `DrawAllTemplateCircles`（模板模式） | 已选点 / 全部模板点 | 读 `shape.LayerHidden` |

**选取（三个独立入口）**

| 入口 | 位置 | 过滤 |
|---|---|---|
| 左键选点 | `KWindowControl_KMouseDown` → `HitTest(…, DepthForHitTest)` | 隐藏图层跳过 + 叠放优先 |
| 右键菜单 | `KWindowControl_ContextMenuRequested`（共用同一个委托） | 同上 |
| 框选 | `ApplyRegionSelection` → `GetCirclesInSelectedRegion` | 隐藏图层跳过 |
| （多选扩散） | `HandleMultipleSelect` | 图层可见 + **同一图层** + 框选限定 |

**绘制顺序**（两个模式必须一致）：底图 → 选点 → 框选限定框（先画的在下层）。

## 七、关键不变量（改代码前必读）

1. **`IsSelected` 与 `_selectedCircles` 是两份状态，必须同步**。清空一律走 `ClearAllSelection()`，
   不要直接 `_selectedCircles.Clear()` —— 残留 `IsSelected = true` 会让后续框选"一个都不响应"。
2. **`_selectedCircles` 里的对象必须是 `_allShapes` 里的同一实例**：
   `HandleSingleSelect` 用 `List.Remove(clicked)` 取消选中，比较的是**引用**；
   两份实例会表现为"点一下能选中、再点取消不掉"。保证机制在 `BuildAllShapes` 的两级索引。
3. **选点不设门禁**：左键任何时候都能选点；单选 / 多选只是"点击语义"，不是开关。
4. **图层状态一律拷进图形对象，绝不用"图层名"做字符串匹配**：
   字符串匹配一旦对不上会**静默退化**为纯距离排序（= 又只能选到最大圆圈那层），且无报错可查。
5. **隐藏图层 = 不画 + 不选 + 数据保留**：四处过滤共用 `IsShapeLayerVisible()`；
   `_selectedCircles` / `_apertures` 不动（所以包围盒不会随显隐跳动）。
6. **图形的唯一键 = 图层 + 坐标(4 位小数) + 形状 + 尺寸**（`ShapeKey`）：
   四维缺一会导致"错位认领"（同一对象被塞进缓存多次、另一个图形消失）。
   使用点三处必须口径一致：`BuildAllShapes`、`ApplyRegionSelection`、`IsSingleShapeInShapes`。
7. **命中测试：先比图层叠放，同一层内再比距离**；最上层该处没图形时穿透到下一层。
   几何库 `ShapeQuery` 保持**无状态**，图层知识由宿主用委托提供。
8. **`Program.FileName` 是隐式全局状态**（静态字段，`MainForm` 之外也有引用）：
   任何一处悄悄改它都会影响别的读取点。真正的状态源应是 `_currentTemplatePath`。
9. **画布背景纯黑**，光圈配色按"对纯黑对比度 ≥ 4.5:1"筛过；颜色转换按 **Halcon 语义**
   （`"green"` = (0,255,0)，不是 GDI+ 的 `Color.Green`）。
10. **文件写入用 `WriteFileAtomic`**（tmp + `File.Replace`），别退回 `WriteAllText`
    —— 写一半崩会留下半截 JSON。
11. **`bin\x64\Debug\Json\` 是真实使用者的模板数据，不可再生** —— 清理 `bin` 前必须确认它安全。
12. **保存落点只有两个来源**（2026-09-21 起）：有归属 → 就地写回 `_currentTemplatePath`；
    **没有归属 → 弹目录选择器，由用户当场指定**。工程里**不存在"全局默认保存目录"**
    （`DefaultSavePath` 设置项已连同 4 个路径管理方法一并删除）。
    任何"从别处拿一个路径去顶替 `_currentTemplatePath`"的写法都是缺陷 —— 它会让「保存」写去另一个目录，
    而状态栏照样报"已保存"，见 `MD文件汇总（AI）/问题&解决方案/参数设置确定按钮改写工程归属.md`。
    选目录类对话框（另存到 / 新工程首次保存 / 打开模板）的起始位置统一走
    `MainForm.GetProjectParentBrowseDir()`：当前工程目录的父目录 → 图层所在目录的父目录
    → 上次打开的工程目录 → 桌面。
13. **读 json 一律走 `JToken` 索引器，绝不用 `dynamic` 点属性读"可能不存在的字段"**：
    它抛 `RuntimeBinderException`（**不是**返回 null），外层 catch 会把整个工程判成
    "选点文件读取失败"、选点全丢。`ReadJsonLayer` / `ReadJsonHeader` / `ReadJsonPosition` /
    `TryReadDouble` 都是这个写法 —— 取不到返回 `null` / `0`，**不抛异常**。
    读端也**不校验 `Version`**。
    🔴 但**"容错"不等于"兼容旧格式"**：`circles.json` 已演到 **v2.5**，
    字段的**缺失容错**（`Layer` → 空串、`Header` → `h1`）保留，而**格式的旧版本兼容是有意断掉的** ——
    v2.0~2.4 的 `Positions[]` 坐标不再解析（用户 2026-09-21 裁定不需要兼容）：
    打开那种老工程，坐标全读成 0、点堆在原点，**属预期而非缺陷**。
    逐字段说明与版本演进见 `MD文件汇总（AI）/系统架构&协议设计/数据格式-circles.json.md`。
14. 🔴 **图层身份必须在 `BuildAllShapes()` 之前分配**（`EnsureLayerIdentity()`）：
    图形的 `LayerId` 取自 `LayerInfo.Id`（初值 0）。Id 还没分配就进 `BuildAllShapes`，
    它会把 0 写进**每一个**图形；紧接着 `RefreshLayerState` 按 `LayerId > 0` 查归属会全部落空，
    把 `LayerDepth` 一律设成 −1 —— **全体深度相同 → 命中排序的"叠放优先"整档静默失效**，
    表现就是"置顶哪个图层都不起作用，还是选到别的层"。
    调用点两处：`FinishProjectLoad`、`AppendLayersFromFiles`。
    构建日志里有自检「⚠ 有 N 个图形没有图层身份」，正常应为 0。
15. **命中排序是四级**（`ShapeQuery.HitTest`）：① 图层叠放 → ② 命中内部优先于"落在容差里"
    → ③ 都在内部时**尺寸小者胜** → ④ 都在容差内时边界近者胜。
    第 ③ 档是**单图层场景下的唯一防线** —— 那时①②两档的 depth 全体相同，若不按尺寸挑，
    圆内部的 `len − r` 会让大圆通吃。
