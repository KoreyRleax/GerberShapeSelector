# 待办 · 说明与规范

> **这个目录是给上位机工程师本人看的**。AI 的逐日过程记录在 `.workbuddy/memory/` ——
> 两者不重复：**待办只在这里维护，不再只写在 AI 日志里。**

## 用法

- 主清单：`待办清单.md`（所有未完成 / 已完成的待办都在这一张表里）
- **完成后不要删除条目**，而是在状态列标注 **✅ 已完成**，并补上完成日期与实际做法。
  这样能回溯"当时想做什么、后来怎么解决的"。
- 作废的条目同样保留，标 **❌ 已作废** 并写明原因（例如"用户指示不再跟踪"）。
- 新增待办：直接往主清单的表里加一行；如果内容多（有方案对比、验证步骤），
  就在清单里写一行摘要 + 一个 `详情见 <文件>` 指针，详情放到
  `MD文件汇总（AI）/问题&解决方案/` 或 `MD文件汇总（AI）/任务&需求/`。

## 状态口径

| 状态 | 含义 |
|---|---|
| ⬜ 未开始 | 已记录，尚未动手 |
| 🟡 待验收 | 代码/文档已就绪，等用户编译、实机验证或表态 |
| ⏸ 暂缓 | 已确认暂时不做（条件不成熟 / 收益低 / 等前置项） |
| ✅ 已完成 | 已做完并确认；条目保留 |
| ❌ 已作废 | 不再跟踪；写明原因 |

## 排版约定

① 按**状态**分节，每节一张表；② 表格必须连续 —— 表头与数据行之间、数据行之间**不得有空行**；
③ 单元格内**不得出现真实换行**，需分段处用 `<br>`。
