## 一、需求

> **用户原话**：

两个功能都要"搬 UI 位置"：V5 里 h1/h2/h3 是右侧面板的一个下拉框、合并是右侧面板的一个按钮，
而本工程的右侧面板**已整体删除**（画布占满横向空间），所以两者都要落到**画布悬浮工具栏**上。

## 二、背景 / 动机

**h1/h2/h3（选点划分）**：一块板上的点需要分派给不同的插针头。V5 的模型是"每个点带一个头类型，
三种类型用三种颜色画"。本工程改造后没有这个维度，所有点只能是一类。

**合并**：两个靠得很近的点常常只需要一个插针位 —— 手工挪点做不到（本工程没有"拖动点"的功能），
所以 V5 给了"点两个 → 取中点生成一个新点"的做法。

## 三、验收目标

> 判据都是"可操作、可判定"的；每条都能在界面上看到结果或在日志里读到证据。

**A. h1 / h2 / h3（工具栏）**

1. 画布悬浮工具栏上出现 `h1` `h2` `h3` 三个**互斥** toggle，初始 `h1` 选中；点 `h2` 后只有 `h2` 亮着。
2. 在 `h1` 下点选一个图形 → 该点用**参数设置里"h1 颜色"**（默认白）画；
   切到 `h2` 再选一个 → 那个点是**黄色**；切到 `h3` 再选一个 → 那个点是**绿色**。
   三种颜色在同一个画面里能一眼分开。
3. **三个头的颜色都能在「参数设置」里改**（与 V5 一致）：对话框里有 `h1 颜色` / `h2 颜色` / `h3 颜色`
   三行，每行 = 一个色块 + 一个「选择颜色」按钮，色块显示当前色。
   改完点「确定」→ 画布上对应的点**立刻**换色（不用等下一次选点）；重启程序后仍是新颜色。
4. 状态栏左端显示当前模式与当前头，形如 `点击方式：单选 · 当前 h2 - 已选择 3 个图形`。
5. **切换头类型不改动已经选好的点**：切到 h2 之前选的那批 h1 点，颜色与归属都不变。
6. 在目标 h 下**重新点一次**一个已选中的点（取消选中），再点一次（重新选中）→ 它归到当前 h。
7. 多选（同类扩散）扩散出来的点，全部归当前 h。
8. 框选新增的点归当前 h；按 `Ctrl+Z` 撤销该次框选 → 这些点的**头类型与选中状态一起回滚**。

**B. 右键菜单**

9. 右键菜单**最上方**出现：`单选` `多选`（互斥打钩，反映当前点击语义）→ 分隔线 →
   `切换到 h1` `切换到 h2` `切换到 h3`（互斥打钩，反映当前头类型）。
10. 点菜单里的 `多选` → 工具栏的「多选」同时亮起（两处状态是同一份，不会各说各话）；
    点 `切换到 h3` → 工具栏的 `h3` 同时亮起。
11. 菜单不关闭的情况下就能看到勾选变了（不用"关掉再右键一次"来确认）。

**C. 合并（工具栏）**

12. 工具栏出现 `合并` toggle；点一下进入合并模式，状态栏提示
    `合并模式：请依次点两个图形（取中点合成一个新点，原点保留；再点「合并」退出）`。
13. 合并模式下依次点两个图形 → 画面上出现**金色轮廓**标出这两个候选（候选**不改变**它们的选中状态）。
14. 第二个点下去 → 立即生成一个新点：坐标 = 两点的**中点**，形状 / 尺寸 / 光圈 ID / 图层
    沿用**第一个**图形，头类型 = **当前 h**；状态栏显示 `合并完成 → 新点 (x, y)，归 h2（原点保留）`。
15. **原来那两个点保留不动**（选点数量 +1，不是 -1）。
16. 再点一次已选为候选的那个图形 → 取消它的候选资格（金色轮廓消失）。
17. 再点工具栏「合并」→ 退出合并模式，候选清空，选点数据与进入前一模一样。
18. 合并模式下**不会**触发单选 / 多选（不会出现"点一下扩散出一批点"）。
19. 新生成的合并点**可以被点中、可以被取消**（它不在任何 Gerber 图形上，靠"游离选点收编"进入命中缓存）。
20. 关闭工程再打开（保存过）→ 合并点原样在，颜色/头类型正确，仍可被点中取消。

**D. 持久化与兼容**

21. 保存后 `circles.json` 的 `Version` 是 `"2.4"`，每条图形记录带 `"Header": "h1|h2|h3"`。
22. **老工程（没有 `Header` 字段）打开后，颜色与行为跟改动前完全一样**（全部读成 h1 = 用户设的那个颜色）。
23. 日志 `logs/yyyy-MM-dd.log` 里有 `切换插针头类型：h2`、`进入/退出合并模式`、
    合并明细（含两个原点坐标与头类型）三行可查。

## 六、技术实现（为什么）

### 6.1 为什么头类型挂在图形上，而不是"按下标分三份列表"

一个点只属于一个头。挂在图形上只有**一份真相**：绘制、保存、导出读的都是同一个字段。
分成三份列表就要处处维护"这个点在哪个列表里"，用户改一次类型要跨列表搬移 ——
多图层改造时已经吃过一次"同一个事实存两份、两处不同步"的亏（`IsSelected` 与 `_selectedCircles`）。

### 6.2 为什么 h1 的默认色保持白，而不是 V5 的红色

V5 是 h1=red / h2=yellow / h3=green，而且**三个颜色都能在它的参数窗里改**。
本工程只把**默认值**改成 h1=white：老工程与老 `circles.json` 里所有点都是 h1（字段缺失即默认 h1），
照抄 V5 会**一打开满屏白点变红点** —— 那是"升了个版本观感全变"，而用户没要求改配色。
**默认值的语义必须与"什么都不改"等价。**

三个头都能在「参数设置」里改颜色（与 V5 的能力对齐）：`h1 颜色` / `h2 颜色` / `h3 颜色` 三行，
每行一个色块 + 一个「选择颜色」按钮。所以"想跟 V5 一样用红色"这件事，用户在界面上点一下就行，
**不需要改代码**（这正是本次补上的、第一版漏掉的部分）。

两条实现上的取舍：

- **h1 的颜色仍存在 `SelectedCircleColor` 这个老设置项里**（只把界面标签写成「h1 颜色」）。
  给它改名当然更整齐，但用户设置是按名字存的 —— 改名会让老用户已经设过的值**静默失效**
  （界面显示白色，而其实他设过别的色）。代价不对等，所以保留原名。
- **h2 / h3 新建设置项** `HeaderH2Color` / `HeaderH3Color`（默认 yellow / green），
  与 h1 共用同一套读写路径（`ParamsForm` 里三行结构完全一样）。

### 6.3 为什么换色要"只在变化时调 SetColor"

`KWindow.SetColor` 内部要做色名 → 画刷的解析。逐点调用意味着 3,852 个点 / 帧都要解析一次；
而实际数据里同类点通常**成片连续**，一次遍历的切换次数远小于点数。
缓存上一次的颜色再比较，成本接近于零，最坏情况（h1/h2/h3 逐点交替）也只退化成逐点调用 ——
上限就是"什么都不做"的开销，不会更差。

### 6.4 为什么合并点必须收进命中缓存

图形缓存 `_allShapes` 是**命中测试 / 框选 / 多选扩散的唯一依据**，而选点的**绘制**读 `_selectedCircles`。
合并点的坐标是两点中点，天然不落在任何光圈上 → 它不会出现在 `_allShapes` 里 → 结果就是
**"画得出来、存得下去，却怎么点都没反应"**，想取消它只剩"清空全部选点"。

V5 里的合并点正是这个状态（V5 的命中只查 `_allShapes`）。本工程对"点了没反应"零容忍
（左键选点门禁就是这么被删掉的），所以补了 `AppendOrphanSelections()`：
把这类点收进缓存，并沿用生成它的图形的 `LayerId`，于是它的图层深度/隐藏状态与同层图形完全一致 ——
**该层被隐藏时它一起隐藏**，不会赖在画面上。

顺带修好的另一件事：以前从 json 恢复的**任何**坐标对不上 Gerber 的选点，都是这种"幽灵点"，
现在一并收编。

### 6.5 为什么右键菜单的就地同步勾选要手写

`ToolStripMenuItem` 的 `Checked` 不会自己跟着状态变 —— 而菜单在点击后**还开着**。
若不就地更新，用户点「多选」后看到的仍是"单选"打钩，只能关掉菜单再右键一次才能确认，
观感上就是"没生效"。所以两个单选项、三个头类型项在各自的 `Click` 里互相刷新勾选。
（这是唯一一处"UI 状态需要手工写两遍"的地方，代价是 4 行赋值；换成 `CheckOnClick = true` 反而会
出现"菜单勾选与真实状态不一致"——因为真实状态是工具栏那份。）

### 6.6 为什么合并"原点保留"而不是"替换成中点"

照 V5 语义（用户说的是"移植 V5 的功能"）。保留的好处是**不可逆操作少一步**：
合并出来了不想要，取消掉新点即可，原来的两个点还在；若合并即替换，误合并就等于丢了两个点。

要改成"替换"（合并后把原来两个点取消选中并移出 `_selectedCircles`），
在 `HandleMergeClick` 生成新点之后加两行即可 —— 已记入待办 T38 等用户定夺。

### 6.7 被否掉的方案

| 方案 | 为什么否掉 |
|---|---|
| 把 h1/h2/h3 做成 V5 那样的下拉框 | 本工程**右侧面板已整体删除**（画布占满横向空间），没有地方放下拉框；用户明确要求"放到工具栏里像单选多选那样" |
| 三个头类型各存一份 `List<SelectedCircle>` | 见 6.1：一个点一个头，存三份就多两处不同步的机会 |
| 切 h 时把**所有已选点**改成新 h | "切过去接着选"是最常见的动作，顺手把已选的一批改掉会造成大面积误归类，且无法一次撤销 |
| 合并点只进 `_selectedCircles`（照 V5） | 会留下"点了没反应"的点 —— 本工程明确不接受（见 6.4） |
| 合并时把候选点直接置为"选中"（照 V5 的部分行为） | 用户只是想合并，不该顺带改变选点数量；而且退出合并模式还得自己取消掉 |
| 用 `CheckOnClick = true` 做菜单勾选 | 真实状态在工具栏那份，`CheckOnClick` 会让菜单自己翻转成与真状态不一致 |
