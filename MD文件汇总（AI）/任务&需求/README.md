# 任务&需求 · 说明与规范

> 这个目录回答一个问题：**"我到底提了什么、做完算不算数"**。
> 每个需求一个文件，**必须写清验收目标**（否则做完无法判断是否达成）。

## 命名

`R-<YYYYMMDD>-<两位序号>-<简短标题>.md`，例：`R-20260921-01-多图层选点与图层顺序.md`

- `R` = Requirement；同一天多个需求用序号区分。
- 标题写"要什么"，不写"怎么实现"（实现属于解决方案）。

## 每个需求文档必须包含

| 段落 | 内容 | 为什么 |
|---|---|---|
| **需求** | 用户原话或等价的准确复述；提出日期 | 防走样，尤其防"我以为你说的是…" |
| **背景/动机** | 为什么提这个需求，现在有什么问题 | 决定取舍时的依据 |
| **验收目标** | **可操作、可判定**的清单：怎么点、看什么现象、什么算通过 | 需求的核心，不可省 |
| **范围** | 明确"包含什么"和"**不包含什么**" | 防 AI/开发扩大改动范围（本工程也踩过） |
| **实现方案** | 最终怎么做的 + 关键参数 + 代码位置 | 回答"怎么做" |
| **技术实现（为什么）** | 为什么选这个方案、权衡、被否掉的替代方案 | 回答"为什么这么做"，用户明确关心 |
| **状态** | 未开始 / 进行中 / 待验证 / **（已完成 日期）** | 与 `MD文件汇总（AI）/待办/待办清单.md` 对应 |

## 与其他目录的分工

- `MD文件汇总（AI）/待办/` —— 还没做的**动作**（含需求的剩余验证步骤）。
- `MD文件汇总（AI）/问题&解决方案/` —— 需求实施**过程中遇到的问题**及其根因/方案优劣。
- `.workbuddy/memory/` —— 给 AI 下个会话恢复上下文的过程记录（逐日日志 + 长期记忆）。
