## 二、背景 / 动机

### 为什么这个问题值得问

"模板文件保存路径"是**单图层时代**留下的东西。那时点「保存」要用户先手输"目标文件夹名"，
再决定存到哪个根目录下 —— 这个设置项就是那个根目录。

改造成「一个工程 = 一个目录」之后，保存语义变成了**就地写回**（有归属就存回原目录）。
于是这个设置项的管辖范围被不断压缩，到本轮为止**只剩一处还在生效**：

| 触点 | 位置 | 性质 |
|---|---|---|
| 「保存」的无归属分支 | `MainForm.SaveTemplateFile` | ✅ **唯一真正决定东西存到哪**：新建工程后第一次保存 → `GetBaseTemplatePath()/<工程名>` |
| 「另存到」对话框初值 | `MainForm.SaveTemplateAs` | 仅当没有工程归属时，只影响对话框**起点** |
| 「打开模板」对话框初值 | `MainForm.LoadTemplateFile` | 仅起点 |
| 首次运行初始化 | `PublicMethod.InitializeSettings` | 写成 `exe\template`，与 `GetBaseTemplatePath` 的兜底逻辑**重复** |
| `SetSavePath(GetCurrentSavePath())` | `MainForm.btnParamSetting_Click` | **死代码**：`ParamsForm_Load` 会在 `ShowDialog` 时用 `GetBaseTemplatePathFromSettings()` 覆盖文本框与 `_savePath`，Load 晚于 SetSavePath → 主窗体传过去的值**一次都没显示过** |

### 它还造成了一个数据分叉的入口（见关联问题文档）

`btnParamSetting_Click` 里有一段"参数设置点确定后把文本框内容回写 `_currentTemplatePath`"。
文本框里装的是 `DefaultSavePath` —— 一个**与当前工程无关的全局默认值**。
于是"打开工程 A → 进去只改个颜色 → 点确定 → 归属被顶掉 → 再点保存写去了别处"。

**这个缺陷与"设置项留不留"其实无关**（那 5 行无论如何都该删），但只要设置项还在，
它就还留着"顶替归属"的弹药。删掉设置项之后，这类代码在结构上就不可能再出现。

## 五、实现方案

### 5.1 无归属时"当场问"（`SaveTemplateFile`）

```csharp
// 有归属 → 就地写回（不变）
// 无归属 → 弹目录选择器，起始位置由 GetProjectParentBrowseDir() 给出
string picked = FolderPicker.PickFolder(
    $"保存新工程 '{folderName}' —— 选择要保存到的上级目录",
    GetProjectParentBrowseDir());

if (string.IsNullOrEmpty(picked))
{
    toolStripStatusLabel1.Text = "已取消保存（工程尚未保存到磁盘）";
    return;                       // 不写任何文件
}
targetFolder = Path.Combine(picked, folderName);
```

用 `FolderPicker` 而不是老式 `FolderBrowserDialog` —— 与「打开工程」「另存到」保持同一套
选目录体验（系统原生 `IFileOpenDialog`，有地址栏、能粘贴路径、能搜索）。

### 5.2 一个方法统一"选目录"类对话框的起始位置

`GetProjectParentBrowseDir()` 的四级优先级：

| 级别 | 来源 | 为什么 |
|---|---|---|
| ① | 当前工程目录的**父目录** | 「另存到」就是"换个地方放同名的工程目录"，从原地出发最顺 |
| ② | 第一个图层所在目录的**父目录** | 新建工程尚未归属。**必须是父目录** —— 见下 |
| ③ | 上次打开过的工程目录的父目录（kind == `template` 时 `LastProjectPath` 就是它） | 沿用"启动记忆"，用户上次在哪干活就回哪 |
| ④ | 桌面 | 与 `GetGerberBrowseStartPath()` 的兜底一致，任何机器上都有意义 |

每一级都要求父目录**实际存在**才采用（`GetParentDirIfExists`）——
否则系统对话框会自己退化到"我的电脑"，那比给桌面更糟：用户丢掉了全部上下文，还得从头点进去。

> **⚠ 为什么必须是"父目录"而不是"图层所在目录本身"**
>
> 选择器返回的目录会再拼上工程名（= 图层所在目录名）：
> `targetFolder = Path.Combine(selectedPath, folderName)`。
> 初值若给"图层所在目录自己"，用户直接确认就会得到
> `…\1516601-00-C\1516601-00-C` —— **白套一层**。
> 给父目录则默认落点恰好是 `…\1516601-00-C`，与 Gerber 素材所在目录同级同名。

### 5.3 为什么连 `PublicMethod.InitializeSettings()` 一起删

它把 `DefaultSavePath` 初始化成 `exe\template`。两个问题：
① 全工程**没有任何调用点**（死代码，`grep` 只搜到定义那一行）；
② 它的功能与 `GetBaseTemplatePath()` 的兜底分支**完全重复**。
设置项没了，它剩下的那行日志也没有意义 —— 整段删除，不留空壳。

## 六、被否掉的方案（以及为什么）

| 方案 | 内容 | 否掉的理由 |
|---|---|---|
| **A. 保留但收缩语义** | 标签改「新建工程默认目录」，删掉回写归属那几行 | **两套落点语义并存**："有归属就地写"与"没归属落到设置里"永远需要用户自己判断，而设置项是全局的、看不见的。而且它仍然是"顶替归属"那类代码的温床 |
| **C. 只修缺陷，不动设置项** | 仅删 `btnParamSetting_Click` 里回写 `_currentTemplatePath` 的 5 行 | 缺陷确实会消失，但设置项**唯一生效的那一处**（无归属时悄悄落到 `exe\template` 或用户设的目录）依然是"保存到哪说不清"的老来源 —— 用户点保存时看不到这个路径、也记不住 |
| **无归属时不弹框，直接用"图层所在目录"当工程目录** | 新建后第一次保存就地写进 Gerber 素材目录 | 会把 `circles.json` 写进**上游给的原始 Gerber 素材目录**：素材一旦更新/被整目录覆盖，选点数据混在里面极难分离；而且素材目录若是只读（共享盘、只读挂载）会直接写失败。弹一次选择器的成本远低于这两类事故 |
| **把落点记进 `circles.json`** | 让工程自带"我该放哪" | 循环依赖 —— 要读出这个字段就得先找到那个文件，不成立 |
| **保留设置项但改名为"上次保存目录"** | 用"上次用的目录"充当初值 | 与③重了：`LastProjectPath` 已经承担了"上次在哪干活"，再加一个近义设置项只会让两个值互相矛盾 |
