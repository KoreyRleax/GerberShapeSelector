## 一、需求（用户原话）

> **需求 1**："现在的工程管理方案有问题，作为用户来讲，我首次新建工程，需要多选 Gerber 文件，
> 然后必须保存才存在工程，但是保存的时候不能自定义工程名。"
>
> **需求 2**："我希望，除了选择 Gerber 文件这种方式，还能够支持将所有文件拖拽到窗口，
> 拖一个文件就是在当前工程新加一个图层，若当前没有工程，那么拖文件相当于新工程。"
>
> **需求 3**："打开工程没有默认工作路径……用户一般会把所有工程目录放在同一个地方。
> 这将导致每次打开工程，总是要去选择一遍，而如果能自主设置默认打开路径，就可以避免这个问题。"
>
> **需求 4**："新建工程时，应先弹出工程名，再弹出打开文件夹对话框，
> 当所有元素加载完已经保存了，而不是等用户去保存。"

## 二、验收目标（可判定）

### A. 新建工程流程

| # | 验收目标 | 判定方式 |
|---|---|---|
| A1 | 点「文件 → 新建工程」**先弹工程名对话框**，再弹文件选择框 | 观察顺序；名字框标题带"第 1 步"、文件框带"第 2 步" |
| A2 | 工程名**可自由输入**，不再被 Gerber 素材目录名绑死 | 输入任意合法名，实际目录名就是它 |
| A3 | 名字框实时显示"将创建在：<完整路径>" | 输入时预览跟着变 |
| A4 | 载入完成后**工程已在磁盘上**，不需要再点「保存」 | 载入后直接去资源管理器看：工程目录 + `circles.json` + 各图层文件都在 |
| A5 | 设过「默认工作路径」时，落点 = `默认工作路径 \ 工程名`，**不再弹位置选择** | 全程只弹 2 个框（名字 + 文件） |

### B. 拖放

| # | 验收目标 | 判定方式 |
|---|---|---|
| B1 | 拖 1 个 Gerber 文件到**已有工程**的窗口 → 图层数 +1 | 图层容器多一行；状态栏"已添加 1 个图层" |
| B2 | 追加的图层在列表**最上方**（= 压在最上层） | 容器首行是新图层 |
| B3 | 追加后**当前工程的归属不变** | 立刻点「保存」，写回的仍是原工程目录 |
| B4 | 追加后**视图不跳**（不重置到适应窗口） | 缩放/平移位置保持 |
| B5 | 追加后**已有选点不受影响**（数量与位置不变） | 状态栏选点数不变 |
| B6 | 拖到**没有工程**的窗口 → 走新建流程（先载入，再问名字，然后自动落盘） | 弹出工程名框（预填 Gerber 所在目录名） |
| B7 | 拖入与已有图层**同名**的文件 → 弹窗询问是否替换 | 弹框文案含该层现有选点数（若有） |
| B8 | 选择"替换" → 用新文件替换该层，**该层选点被清空**，其余图层选点不受影响 | 容器行数不变；被替换层的点消失 |
| B9 | 选择"否" → 跳过该文件，**不动任何现有数据** | 汇总提示里列出"与已有图层同名，已跳过" |
| B10 | 拖入**文件夹** → 提示改用「文件 → 打开工程」 | 弹框说明，不尝试载入 |
| B11 | 拖入 `.txt` 等非图层文件 → 跳过并**汇总提示原因**，画布不受影响 | 一个提示框列出文件名 + 原因 |
| B12 | 拖到画布 / 工具栏 / 状态栏 / 路径栏**都生效** | 四处各试一次 |
| B13 | 拖入其他内容（选中的文字、URL）→ 光标显示禁止符，落下无反应 | 不接受即无副作用 |

## 四、实现方案

### 1. 工程名自定义（需求 1 + 4）

- 新增 `SaveProjectDialog.cs`（工程名 + 保存位置 + **落点实时预览** + 目录已存在确认）
  → 接入「首次保存」的无归属分支与「另存到」。
  于是**另存到同一父目录 + 改名 = 工程改名**，不用再引进第二条改名路径。
- 新增 `ProjectNameDialog.cs`（只问名字 + "将创建在"预览）→ 用于新建工程的第一步。
- 🔴 **落点规则一个字没改**：有归属仍就地写回 / 无归属才当场问。两个对话框都只是"让用户看得见会存到哪"。

### 2. 新建工程流程（需求 4）

```
「文件 → 新建工程」
  ① ProjectNameDialog        问工程名（可改，不是从目录名推）
  ② OpenFileDialog           多选 Gerber 文件（保持多选，用户已确认）
  ③ LoadProjectFromFiles     清空重建
  ④ AutoSaveNewProject       落点 = 默认工作路径\工程名；不可用时才弹 SaveProjectDialog
```

`AutoSaveNewProject` 与「首次保存」是**同一套落点语义**，区别只是它发生在载入之后、不需要用户先点保存。

### 3. 拖放（需求 2）

- `MainForm` 与 `kWindowControl1` **双挂** `AllowDrop`（鼠标落点几乎总在画布上）；
  两处用同一个处理函数，所以拖到工具栏 / 状态栏 / 路径栏同样生效。
- 分派：`_layers.Count == 0` → 与「新建工程」等价（先载入、成功后再问名字）；
  否则 → `AppendLayersFromFiles`。
- 🔴 `AppendLayersFromFiles` 的红线（与 `LoadProjectFromFiles` 的差别）：

  | 必须 | 原因 |
  |---|---|
  | ❌ 不调 `ResetProjectState()` | 它会连图层、选点、**工程归属**一起清掉 |
  | ❌ 不动 `_currentTemplatePath` / `_isTemplateMode` | 归属必须保住，否则"拖一层进来"变成"工程没了" |
  | ❌ 不调 `ResetViewToCenter()` | 用户正盯着某处，追加一层不该把视图甩走 |
  | ✅ 新图层追加到 `_layers` 末尾 | 末位 = 最后绘制 = 压在最上层 |
  | ✅ `ColorIndex` 留 −1、`Id` 留 0 | 交给 `EnsureLayerIdentity` 现分配 |

- 同名替换：`ReplaceLayer` 保留原 `Id` / `ColorIndex` / `IsVisible` 与**列表位置**，
  但**清掉该层选点**（图形对象整批换新，旧选点会成为"点不中的幽灵点"），
  并**剔除框选撤销栈里引用旧图形的快照**（否则撤销会把幽灵点加回来）。
- 抽出 `TryParseLayerFile(path, out layer, out reason)`，两条路径共用 ——
  否则第二份解析逻辑必然与第一份漂移。

### 4. 默认工作路径（需求 3）

- 新增设置项 `DefaultProjectRootPath`（默认空）+ 「参数设置」最上面一行（可手输 / 可浏览）。
- 接入 `GetProjectParentBrowseDir()` 的**第 ⓪ 级**（最优先）。
- 🔴 **它与已删除的 `DefaultSavePath` 的关键区别**：
  那个设置项当年**越界**了 —— 被 `btnParamSetting_Click` 拿去顶替 `_currentTemplatePath`，
  于是"打开工程 A → 改个颜色 → 点确定 → 再保存"会把内容写去别处。
  新项**只做对话框初值，绝不参与落点决策**（验收目标 C5 就是守这条）。

### 5. 两个配套修正（不改就没法用）

| # | 问题 | 修法 |
|---|---|---|
| 1 | 保存图层时按"目标文件是否存在"跳过复制 → 拖入**替换**的同名图层保存后等于没发生过（工程目录里还是旧文件） | 判据改成 `IsSamePath(targetLayerPath, layer.FilePath)`：同一个文件才跳过，同名不同源一律覆盖 |
| 2 | `FinishProjectLoad` 里 `BuildAllShapes()` 早于图层 Id 分配 → 图形的 `LayerId` 全被写成 0 → `LayerDepth` 全为 −1 → **命中排序的"叠放优先"静默失效（置顶无效）** | 抽出 `EnsureLayerIdentity(depthOf)`，在 `BuildAllShapes()` **之前**调用（`FinishProjectLoad` / `AppendLayersFromFiles` 两处）；并在构建日志里加自检"没有图层身份的图形数" |

第 2 条详见 `MD文件汇总（AI）/问题&解决方案/选点只能选到最大圆圈那一层.md` §5.5。

## 五、被否方案与理由

| 方案 | 否掉的理由 |
|---|---|
| **界面上常驻一个可编辑的工程名输入框** | 打破"工程名 = 目录名"这个模型：输入框里的名字和磁盘目录名可以不一致，改名就得 `Directory.Move`（要动已存进去的 Gerber + json，还要处理目录被占用）。为一个改名把模型搞复杂，不值 |
| **用 `SaveFileDialog` 冒充"名字 + 位置"** | 要关掉扩展名与覆盖检查（`ValidateNames=false`），用户会以为在选文件。是 hack，且与本工程"选目录一律用系统原生 IFileOpenDialog"的风格不一致 |
| **拖入文件夹 = 自动扫描图层**（当作新建） | 用户已确认第二步是**选 Gerber 文件**；且"拖目录"与「打开工程」的语义会重叠，容易出现"我明明想加一层，它却把整个工程重载了" |
| **拖放新建不弹名字，用 Gerber 目录名自动落盘** | 那就回到"工程名不可自定义"的老问题，与需求 1 直接冲突 |
| **同名图层"再加一个"（允许重名）** | 图层身份标识（勾选 / 置顶按名字找对象）会打架；用户也确认要"**弹窗询问是否替换**" |
| **默认工作路径复用旧 `DefaultSavePath` 的字段名** | 旧字段的语义是"保存落点"，复用等于把那条越界逻辑请回来。新字段名 `DefaultProjectRootPath` 从名字上就限定为"工程们的根目录" |
