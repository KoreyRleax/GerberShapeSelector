## 一、背景 / 动机

插针机按**坐标**定位打针：它读 `Shapes.*[].X` / `.Y` 与尺寸，**不读 `Layer`**
（下游全目录 grep 确认，见 T41）。所以同一个坐标上出现多条记录 = **同一个位置被插两次针**，是交付缺陷。

而本项目的选点模型允许"不同图层、同坐标"各占一条（图形唯一键含图层维度）。这个组合本身没错，
错的是**没有任何一处拦它**。产生重复的实际路径只有三条 —— **单选不会**（左键点一下走
`ShapeQuery.HitTest`，按图层叠放取胜者，同一坐标永远只点得到最上面那条）：

| 路径 | 位置 | 为什么没去重 |
|---|---|---|
| **框选**（主因） | `MainForm.cs:3453-3469` | 判"是否已选"用的是四维键 `ShapeKey`（图层+坐标+形状+尺寸），跨图层同坐标是**两个不同的键** → 两条都进 `_selectedCircles` |
| 隐藏上层 → 点下层 → 重新显示上层 | 规则 R1「隐藏 = 不画 + 不选 + **数据保留**」 | 隐藏时旧点还在数据里，用户以为那坐标没点，于是又选了新的 |
| 合并点 / 游离点恰好落在已有坐标上 | `MainForm.cs:1267-1277` | `CreateMergedShape` 取两点中点，不查全局坐标 |

保存端 `SaveTemplateToPath`（`MainForm.cs:4918`）**落盘前零查重**，直接按形状分组写出。

## 二、验收目标

前置：准备一个多图层工程，让**同一坐标在不同图层上各有一个图形**（`GBL` 与 `GBS` 常有此情形）。

| # | 怎么操作 | 什么算通过 |
|---|---|---|
| 1 | 框选那片区域 → 点「保存」 | 弹出「同坐标重复点」对话框，标题写明"发现 N 处…（涉及 M 个点）"，明细里该坐标下列出**两条记录**（图层名 / 形状尺寸 / 头类型） |
| 2 | 在对话框里点「返回修改」 | 再弹一个「保存未执行」提示；**磁盘上 `circles.json` 的修改时间不变**（这是"一个文件都没写"的硬判据） |
| 3 | 重新点「保存」→ 这次点「仍然保存」 | 正常保存成功；`circles.json` 里那两条记录**都在**（不自动删）；`logs\` 里有 `WARN` 行：「用户确认在 N 处同坐标重复点存在的情况下仍然保存」 |
| 4 | 造一个**没有**重复点的工程 → 点「保存」 | 流程与改动前**一字不变**：不弹任何新窗口、不看日志能察觉不到这次改动 |
| 5 | 重复点弹窗上按 **回车** | 等价于「返回修改」（**不是**"仍然保存"）—— 默认动作必须是不写盘的那个 |
| 6 | 把某图层隐藏后保存（该层有点在冲突坐标上） | 明细里那条带 `⚠ 该图层当前已隐藏`（提醒"看不见的层也会被写进 json"） |
| 7 | 用「新建工程」流程载入一个没有选点的工程 | 自动落盘**不受影响**（无选点 → 不弹窗） |
| 8 | 打开一个 v2.0~2.4 的老工程（坐标会全读成 0），点保存 | 应弹出**大量**冲突（都在原点），提示语第二行变成"⚠ 重复数量异常多时…"—— 这正好**拦住**"把全 0 写回去"这个不可逆操作 |

## 三、范围

**包含**：保存前的同坐标检出 + 弹窗阻断 + 冲突明细（弹窗与日志共用一份文本）+ 新增对话框文件。

**不包含**（明确划界，避免被顺手扩大）：

- **不做自动去重**。点还在，只是被拦下 —— "保留哪一条"是业务判断（见 §六-3）。
- **不改选点行为**。选点仍不设门禁：不因为"这个坐标已经有点"就拒绝选点、不静默替换旧点。
- **不改图形唯一键 `ShapeKey`**。四维键管的是"选点对象 ↔ Gerber 图形"的对应，与本次无关（§六-1）。
- **不动"隐藏图层的点仍会导出"**。那是 T42 的独立决策；本次只是把它**标出来**。
- **不引入坐标容差**。判重口径 = 落盘口径（4 位小数、同一次 `Math.Round`）。
- 不提供"本工程不再提示"的开关（每次保存都警告，这正是"警告"的意义）。

## 四、实现方案

| 位置 | 内容 |
|---|---|
| `DuplicatePositionDialog.cs`（新增，已登记 csproj） | 警告框：标题 + 提示 + 只读明细框（Consolas 等宽）+「返回修改」/「仍然保存」。**零业务判定** —— 明细文本由 MainForm 拼好传入 |
| `MainForm.FindDuplicatePositionGroups()` | 按落盘坐标分桶，挑出容量 > 1 的组；组内按 `LayerDepth` **降序**（最上层在前）；组间按坐标升序 |
| `MainForm.DescribeShapeSize()` | 单个点的形状尺寸描述（与保存端字段口径一致） |
| `MainForm.BuildDuplicateDetailText()` | 拼明细（弹窗与日志共用）；最多显示 50 处（`DuplicateDetailMaxGroups`），超出部分只进日志 |
| `MainForm.ConfirmNoDuplicatePositions()` | 检出 → 写日志 → 弹窗 → 用户选「返回修改」则返回 `false` |
| `MainForm.SaveTemplateToPath()` 开头 | 调 `ConfirmNoDuplicatePositions()`，`false` 即 `return false`（**任何文件都不写**，图层拷贝与 json 全部跳过，工程归属也不更新），且位置在"是否覆盖"确认**之前** |

日志：`logs\yyyy-MM-dd.log`，搜 `保存前预检` 可看到汇总；明细用 `WARN` 级别写全量。

## 五、技术实现（为什么）

### 1. 「图形唯一键」与「选点集合的去重口径」是两个概念

| 概念 | 内容 | 本次是否动 |
|---|---|---|
| **图形唯一键** `ShapeKey`（`MainForm.cs:2988`） | 图层 + 坐标 + 形状 + **尺寸**，四维 | 🔴 **没动**。它是"选点对象 ↔ Gerber 图形"的一一对应表；少了图层维度就会静默退回纯距离排序（就是 2026-09-21 刚修完的"只能选到大圆"）。详见 `MD文件汇总（AI）/问题&解决方案/重复坐标的图形互相顶替.md` |
| **选点集合的去重口径** | 本次新增：**只认坐标** | ✅ 新增了一条独立的口径：交付给插针机的落点集合里，一个坐标只能有一个点 |

所以"改模型"并不需要动那个四维键 —— 但也没有走"改模型"这条路，理由见下条。

### 2. 为什么拦在保存（出口），而不是选点（源头）

1. **一个门 vs 五个门**：选点入口有五处（单选 / 多选扩散 / 框选 / 合并 / 游离点收编），逐个设防必漏；
   `SaveTemplateToPath` 是**唯一**的写盘点（新建自动落盘、就地保存、另存为都汇到这里）。
2. **隐藏图层场景在选点端判不准**：藏起来的旧点算不算存在？算 → 用户莫名其妙被拒；不算 → 重复照样产生。
   这个悖论只有落到出口才消失。
3. **只有出口能覆盖老工程里已存下的历史重复点**。
4. **不静默丢数据**：出口只是"拦 + 告知"，点还在用户手里。

### 3. 为什么只警告、不自动去重

"保留哪一条"程序猜不准：`GBL` 与 `GBS` 常在同一坐标放**不同尺寸**的图形（焊盘与它的外形框），
插针机要打的通常是其中某一条。按"最上层"或"尺寸最大"去猜都可能猜反 —— **猜反就是打错针位**，
比报错严重。所以程序只负责把冲突摆清楚（坐标 + 图层 + 形状尺寸 + 头类型），决定权交回用户。

### 4. 判重口径 = 落盘口径

两边都是 `Math.Round(…, 4)` —— **同一次舍入**，于是比对即精确相等，不需要引入容差。
这也是为什么不用 `ShapeKey` 去判重：那个键含图层与尺寸，会把"跨图层同坐标"判成两个不同的点。

### 5. 两个边界（实测记录）

- **负零不需要额外归一**（想过这一层，被实测否掉）：`Math.Round(-0.00003, 4)` 确实得到 `-0.0`
  （位模式 `0x8000000000000000`，与 `+0.0` 不同），但它与 `+0.0` 的 `GetHashCode()` **相同**（都是 0）、
  `Equals` 为 true，作为 `Dictionary` 键**可以互相命中**，不会漏判。
  实测环境：`.NET Framework 4.8.9345.0`（正是本工程的运行目标）。
- **`Math.Round` 默认是银行家舍入（ToEven）**：`Math.Round(35.12345, 4) = 35.1234`，
  而 `Math.Round(35.12346, 4) = 35.1235` —— 两个只差 `1e-5` 的邻居可能落到**不同的 4 位小数**上，
  于是**不会被判为重复**。这不是本次引入的问题（**落盘时也是这么舍入的**，所以它们在
  `circles.json` 里本来就是两个不同坐标，插针机也会打两针，间距 0.0001 mm = 0.1 µm）。
  若要覆盖这种"肉眼同一位置"，需要另立口径（例如引入 0.001 mm 的容差）——**本次没做**。

## 六、被否掉的方案

| 方案 | 结论 |
|---|---|
| **保存前检出 + 弹窗（采用）** | 一个门、不丢数据、能覆盖历史数据；代价是"要等到保存才知道" |
| 改选点行为：同坐标只允许一个点，新点替换旧点 | **否**。与两条既有红线冲突（「选点不设门禁」、「隐藏 = 数据保留」）；隐藏场景会**静默**丢点；
且动不到老工程里的历史重复数据 |
| 把 `ShapeKey` 改成"坐标唯一"（去图层维度） | **否**。会破坏刚落地的多图层命中（"只能选到大圆"复发），
且丢掉了"同坐标不同尺寸的焊盘/外形框各自独立"这条已修的行为 |
| 保存时自动去重（每组保留最上层 / 尺寸最大） | **否**。见 §五-3：猜错就是打错针位，且属于"替用户删数据" |
| 检出后自动高亮冲突点 | **暂不做**。需要维护"冲突快照 + 失效清理"一套状态，本轮先从最小可用做起；
需要时再加 |
| 在明细里给出坐标容差比对（0.001 mm） | **否**（本轮）。口径必须与落盘一致，否则会出现"弹窗说有重复、
但存下来是两个坐标"的自相矛盾 |

## 七、补充：本轮顺带发现（未改，仅记录）

- 保存写出的是 `_selectedCircles` **全部**，不看 `IsSelected` —— 所以"当前未选中"的点也会进
  `circles.json`（`TemplateInfo.SelectedCount` 与 `TotalCount` 两个字段的存在即源于此）。
  本次**只在明细里把它标出来**（`⚠ 当前未选中`），没有改行为。
- `_selectedCircles` 里可能存在 `IsSelected == false` 的残留，来源与是否该清理属于另一个问题。
