## 三、根因

**每帧成本 ≈ 视野内图元数 × 单次绘制成本**，而这两项同时不利：

1. **视野内图元数随缩放按面积增长**。缩到 1/N，视野面积 ×N²。
   实测（视野以板心居中，阈值 3px）：

   | 缩放倍数 | scale | 视野内图元 |
   |---|---|---|
   | 1×（默认整板） | 4.88 | **20 188** |
   | 2× | 9.76 | 8 199 |
   | 4× | 19.5 | 2 167 |
   | 8× | 39.1 | 804 |
   | 16× | 78.1 | 123 |

   → **放大后本来就快**；卡的是"整板 / 缩小"这一档。
2. **单次成本被"描边"放大**。底图走 `SetDraw("margin")` = 描边圆，
   GDI+ 要光栅化曲线 + 抗锯齿：3~5px 的图形单次 **2.42~2.69 μs**，
   而画一个**同尺寸实心方块**只要 **0.65~0.72 μs**（见 §五 实测表）。

按**每个光圈实际的屏幕尺寸**查 §五 的实测成本表再累加（离屏 GDI+、抗锯齿开、Release）：

| 方案 | ms/帧 | 相对现状 |
|---|---|---|
| 现状：全部精确描边 | **≈ 56** | 1.00x |
| 只跳过 < 2px | ≈ 56 | 1.00x（**没有可跳的**） |
| **< 5px 改用同尺寸实心方块** | **≈ 16.5** | **0.30x** |

其中 **3~5px 那一档（15 660 个）独占约 32 ms（57%）** —— 它是成本大头，所以阈值必须覆盖到它。

> ⚠ 口径更正：本条最初报的是 `76 ms / 18 ms`，那是按"每个尺寸档取一个代表值"粗算的；
> 改成"按每个光圈的实际屏幕尺寸插值累加"后是 **56 ms / 16.5 ms**，更准。**以后者为准。**

## 四、解决方案：按屏幕尺寸分级（连续 LOD）

落点：`MainForm.DrawGerberApertures`（`MainForm.cs:1916` 起）+ 两个常量 + `LodTierOf`（`MainForm.cs:1893`）。

| 图形的屏幕尺寸 | 画法 | 单次成本 |
|---|---|---|
| < 1.0 px | 不画 | 0 |
| **1.0 ~ 5.0 px** | **同尺寸实心方块** | 0.5~0.9 μs |
| ≥ 5.0 px | 精确绘制（描边圆 / 矩形 / 椭圆） | 2.4~4.5 μs |

四个设计要点：

1. **判据用"屏幕尺寸"，不用"缩放级别"**。屏幕尺寸 = 世界尺寸 × scale，
   所以它**自动**等价于"越缩小越粗、越放大越精细"：放大后所有图形自己回到精确档。
   不必维护"当前第几档"的状态，也就不会出现切档时的画面跳变。
2. **方块边长 = 图形自身的外接框**（不是固定 2×2 像素）。这样**视觉尺寸完全不变**，
   抹掉的只是"圆 / 椭圆"这层形状细节。
3. **只作用于底图**（Gerber 光圈）。选点 `_selectedCircles` 永远精确绘制 ——
   "看不清"与"选不了"是两回事，后者是缺陷。
4. **每图层内分两趟画**（先精确档、再简化档）：把 `SetDraw` 状态切换降到"每图层 1 次"
   而不是"每图形 1 次"；而两趟又**必须放在图层循环内部** ——
   挪到外面会让上层的简化图形盖住下层的精确图形，直接把图层叠放顺序搞乱。

阈值集中在两个常量，改一处即可：
`LodSkipPx = 1.0`（`MainForm.cs:1858`）、`LodBlockPx = 5.0`（`MainForm.cs:1887`）。

### 4.1 为什么是 5px（不是 4 也不是 8）—— 把"阈值 → 收益"曲线打出来看拐点

同一块板、同一套实测成本，**按每个光圈的实际屏幕尺寸插值**累加：

| 阈值 px | 降级占比 | 预估 ms/帧 | 相对现状 | 本档比上一档**再**省 |
|---|---|---|---|---|
| 1.0 | 0.0% | 55.8 | 1.00x | 0.0% |
| 2.0 | 0.0% | 55.8 | 1.00x | 0.0% |
| 3.0 | 19.1% | 48.8 | 0.87x | 12.7% |
| 3.5 | 20.9% | 48.1 | 0.86x | 1.2% |
| 4.0 | 58.1% | 33.4 | 0.60x | 26.3% |
| **4.5** | **96.5%** | **16.6** | **0.30x** | **30.1%** |
| **5.0** | **96.7%** | **16.5** | **0.30x** | **0.1%** ← 取它 |
| 6.0 | 96.8% | 16.4 | 0.29x | 0.2% |
| 8.0 | 98.3% | 15.5 | 0.28x | 1.4% |

- 🔴 **拐点在 4.5px**：过了它收益就进平台 —— 4.5 → 8.0 只再省 **1.4%**。
  再往上调等于"白拿观感换空气"。取 **5.0** 是让它落在平台起点、留一点余量
  （4.5~5px 之间还有个小尾巴）。
- **为什么不是 3px**：只覆盖 19.1%、0.87x —— 几乎没省。因为 2~3px 那档的描边本来就便宜
  （2.42 μs），而不是因为它数量少。
- **为什么不是 4px**：0.60x，省 40% —— 但 3~5px 里最贵的 4~5px 那半没被覆盖。
- **为什么不是 8px**：只在 5px 基础上再省 2%，却要动到"已经能看出圆角"的图形。

### 4.2 为什么是 1px（`LodSkipPx`）

1px 是**光栅化的物理边界**：小于它，图形最多覆盖 1 个像素，抗锯齿还会把它摊成一个更暗的点。

⚠ 但要说清：**它在这块板上的触发次数是 0**（最小图形 2.2px）。所以它**不是用来省时间的**，
是"用户手动缩到 1/5 以下"时的兜底。**真正省时间的是 5px 那一档，别指望 1px。**

> 一个补充：`5px` / `1px` 这类数字是**屏幕像素**，会随窗口大小与 DPI 自动缩放 ——
> 窗口变大 → 同一图形占更多像素 → 更少被降级（画得更精）。这正是想要的行为。
> 而"收益占多少比例"是**这块板的分布**决定的，换一块图形普遍更大的板，同一个 5px 收益会变小 ——
> 那时按 §4.1 这张曲线重定即可。

## 五、实测数据（离屏 GDI+，抗锯齿开，Release，3 轮取中位，每种 20000 个）

每图形单次成本（μs）：

| 屏幕直径 | 描边圆 | 填充圆 | **同尺寸方块** | 方块 / 描边 |
|---|---|---|---|---|
| 1 px | 1.73 | 1.04 | 0.50 | **0.29x** |
| 2 px | 2.44 | 1.31 | 0.59 | **0.24x** |
| 3 px | 2.42 | 1.43 | 0.65 | **0.27x** |
| 4 px | 2.69 | 1.63 | 0.72 | **0.27x** |
| 6 px | 3.80 | 2.01 | 0.87 | **0.23x** |
| 8 px | 3.93 | 2.11 | 1.05 | **0.27x** |
| 12 px | 4.49 | 2.55 | 1.43 | **0.32x** |
| 20 px | 6.44 | 3.99 | 4.11 | 0.64x |

即 **1~12 px 区间，同尺寸方块稳定便宜 3~4 倍**；20 px 以上优势才收窄（但那种图形数量极少）。

## 六、被否掉的方案（这段最值钱）

| 方案 | 结论 |
|---|---|
| **只跳过亚像素图形**（最初设想的主要形式） | **单做它没用**。真实板上 < 2px 的图元是 **0 个** —— 工艺尺寸下限摆在那里。该档保留了（`LodSkipPx`），但真正起作用的是"方块替换"那一档 |
| **合并成一条 `GraphicsPath` 再画** | **否，实测更慢**。20000 个椭圆合成一条路径后 `DrawPath` = **562 ms**，是逐个描边（162 ms）的 **3.5 倍**；`FillPath` 也有 1.89 倍。GDI+ 的路径 figure 一多，内部开销超线性 —— 这条"看起来最诱人的批量优化"被实测否掉 |
| **按缩放级别整档切换**（如"整板视图下全部画点"） | 否。大焊盘也被抹掉，底图会变成点阵图。改成"按每个图形自己的屏幕尺寸"判定后，它是连续的、放大后自动恢复 |
| **整体把描边改成填充** | 部分采用（简化档内部就是填充），但**不整体改**：底图靠轮廓线区分图层层次，整体填充会让叠加的图层糊成一片 |
| **交互期降级 + 静止后精绘**（GUI 常见做法） | **本轮不做**，留作下一步。控件库没有暴露"正在拖拽 / 缩放"的状态，需要自己挂鼠标钩子 + 静止计时器；而静态分级已把 76 ms 压到 18 ms，先看实机手感再决定要不要加这一层 |
| **位图缓存**（视口不变时复用） | 否（本轮）。它只解决"平移 / 重复重绘"，不解决缩放；而缩放正是用户报的场景 |

## 七、边界与遗留

- **观感代价**：默认视图下约 **96.7%** 的图元会从"描边圆"变成"同尺寸方块"。
  5px 以下肉眼分不出圆方，但**密集区域的亮度会略升**（方块面积是内切圆的 4/π ≈ 1.27 倍）。
  若觉得底图观感变了，把 `LodBlockPx` 从 5.0 调到 2.0 即可（只影响真·亚像素，代价是省得少）。
- **模板模式同样受益**（走同一个 `DrawGerberApertures`），但
  `DrawAllTemplateCircles`（画选点）**不做分级** —— 若将来选点数上万，需要另议。
- 本文的 `56 ms → 16.5 ms` 是**离屏 GDI+ 的纯绘制时间**，不含控件库包装与 WinForms 消息循环；
  实机数字以手感为准。
