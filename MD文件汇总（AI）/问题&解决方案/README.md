# 问题&解决方案 · 说明与规范

> **这个目录是给上位机工程师本人查的**：遇到症状时按"问题点"找文件，直接看根因与方案。
> 每个文件回答三件事：**现象是什么 → 为什么（根因）→ 怎么解决（含优劣、被否掉的方案）**。

## 命名

- **以问题点命名**，不加日期前缀（查的时候是按症状找，不是按时间找）：
  例 `选点只能选到最大圆圈那一层.md`、`隐藏图层的选点仍然可见可点.md`
- **一个问题一个文件；类似问题放同一个文件**，在文件内用小节区分。
- 文件名里如含 `/ \ : * ? " < > |` 之类非法字符需替换（Windows 限制）。

## 每个问题文档建议包含

| 段落 | 说明 |
|---|---|
| **现象** | 用户看到的现象 + 复现条件；最好带用户原话 |
| **影响** | 有多严重、影响哪些功能 |
| **定位过程** | 怎么找到根因的（测点 / 日志 / 二进制核对等），**保留证据**（数字、文件尺寸、日志行） |
| **根因** | 机制层面的解释，不要停在"某函数慢" |
| **解决方案** | 最终做法 + 关键代码位置 + 参数 |
| **优劣 / 备选方案** | 为什么选它；被否掉的方案为什么否（**这一段最值钱**） |
| **遗留** | 未解决的边界、需要用户决策的点、后续可优化项 |

## 与其它目录的关系

- `MD文件汇总（AI）/任务&需求/` —— 需求本身（提了什么、验收目标）。
- `MD文件汇总（AI）/待办/` —— 还没做的动作。
- 本目录 —— 需求实施过程中**踩到的坑**与**技术问题的解法**（含环境类问题）。
