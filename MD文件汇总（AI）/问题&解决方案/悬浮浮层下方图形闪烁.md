## 一、现象

画布上有两块**半透明浮层**（顶部工具栏、右上角图层容器）。缩放 / 平移 / 刷新时，
**浮层覆盖的那块区域**里的 Gerber 图形会闪 —— 浮层自己的底和文字不闪，闪的是"它下面那层图"。

## 二、根因：半透明浮层是"绘制模拟"，而它**没有双缓冲**

### 2.1 控件库的"透明链"设计（`OverlayToolbar.cs:14-22`）

WinForms 的"透明子控件"不是真透明，而是**绘制模拟**：
子控件 `OnPaintBackground` 时先回调**父控件的 `OnPaintBackground`** 把底下那块内容画出来，
再叠自己的半透明 `BackColor`（GDI+ 的 `SolidBrush` 支持 alpha，所以能真合成）。

所以这条链上**每一环都必须在 `OnPaintBackground` 里画**：

```
KWindowControl.OnPaintBackground        ← 画画布内容（不是 OnPaint！）
  └─ OverlayToolbar.OnPaintBackground   ← Panel 的半透明底
       └─ OverlayToolbarButton.OnPaintBackground  ← 透明，等于不画
```

> 这也解释了 `KWindowControl.cs:23-31` 那句"绘制必须发生在 OnPaintBackground 里"的非常规设计 ——
> 内容若画在 `OnPaint` 里，透明子控件底下会露灰。

### 2.2 两边的双缓冲状态**不一致**（这才是闪烁的直接原因）

| 控件 | 双缓冲 | 出处 |
|---|---|---|
| `KWindowControl`（画布） | ✅ `ControlStyles.OptimizedDoubleBuffer` | `KWindowControl.cs:115-119` |
| `OverlayToolbar`（工具栏 + 图层容器） | ❌ **没设** | `OverlayToolbar.cs:53-71`（只设了 `SupportsTransparentBackColor`） |

`Panel` / `FlowLayoutPanel` 的 `DoubleBuffered` 默认就是 `false`。

### 2.3 于是发生了这件事

浮层每次重绘要走**两步**：① 让父控件（画布）把那块内容画出来 → ② 叠半透明底。

- **画布**有缓冲：画进内存位图 → 一次性 blit，中间态看不见 ✓ **所以画布本体不闪**
- **浮层**没有缓冲：①②**直接往屏幕上画** → 在"①刚画了一半"的窗口期里，
  浮层覆盖的那块就露出中间态 → 肉眼看到的就是**浮层下方的图形在闪**

对比之下更显眼：周围区域有缓冲、稳稳的，就那一块在抖。

### 2.4 但还有一条**更根本**的原因：视口变化时浮层压根没被重绘

`KWindowControl.OnViewportChanged`（`KWindowControl.cs:233-238`）：

```csharp
private void OnViewportChanged(object sender, EventArgs e)
{
    Invalidate();          // ← 无参 = invalidateChildren: false
    ...
}
```

`Invalidate()` 无参等价于 `Invalidate(false)` —— **不失效子控件**，而浮层（工具栏 / 图层容器）
**正是子控件**。于是**滚轮缩放 / 平移时浮层根本不重绘**，它覆盖的那块会**停在缩放前的旧画面上**，
直到它因别的原因（鼠标移进去、显隐切换、整窗刷新）才重绘 —— 用户看到的就是
"**浮层下方的图形滞后 / 跳一下**"。

> 🔴 这一条比 §2.3 更根本：**双缓冲只能让"重绘时不露中间态"，而"压根不重绘"是一直显示旧内容。**
> 两条都要修 —— 见 §三。

## 三、解决方案（两处，都在本工程侧）

### 3.1 让浮层跟着视口变化重绘 ← 主要修复

本工程订阅了 `KWindowControl.ViewChanged`（`MainForm.cs:750` → `OnViewChanged`，
原来只在那里刷状态栏）。补一句即可：

```csharp
kWindowControl1.Invalidate(true);   // 参数 true = 连子控件一起失效
```

反复 `Invalidate` 只是**标脏**，会在下一个 `WM_PAINT` 里合并成一次，不会多画一遍；
也不会造成递归（浮层重绘只是回调画布的 `OnPaintBackground` 补底，**不改视口**）。

### 3.2 给浮层开双缓冲（消除重绘时的中间态）

`Control.DoubleBuffered` 是 **protected**，外部设不了 → 开个只设一次属性的子类：

```csharp
private sealed class DoubleBufferedOverlayToolbar : OverlayToolbar
{
    public DoubleBufferedOverlayToolbar()
    {
        DoubleBuffered = true;   // 半透明浮层 + 无缓冲 = 闪烁；这一行就是全部修复
    }
}
```

两处 `new OverlayToolbar()` → `new DoubleBufferedOverlayToolbar()`：
`BuildOverlayToolbar()`（顶部工具栏）与 `BuildLayerPanel()`（右上角图层容器）。

可行性已核对：`KWindowControl.AttachOverlayToolbar(Control toolbar, ToolbarEdge edge)`
（`KWindowControl.cs:354` 与 `:360`）的参数类型是 **`Control`**，接子类没有任何问题。

**代价**：浮层各多占一块内存位图（几十 × 几百像素），可忽略；**无观感变化**（半透明仍是半透明）。

## 四、被否 / 留作下一步

| 方案 | 结论 |
|---|---|
| **本工程侧子类开双缓冲**（采用） | 最小代价、零外溢；浮层闪不闪**只跟浮层自己**有关 |
| 直接改控件库 `OverlayToolbar` 的构造函数 | **本轮没做**。加一行 `DoubleBuffered = true;` 更彻底（所有引用该 dll 的工程都受益），但 `Korey.SmartWindow` 是**共享自研库**，属共享变更 —— 先留在本工程侧解决；若别的工程也报这个现象，再考虑提到库里 |
| 把浮层背景改成**不透明** | **否**。透明链的根就在"要看到底下的图"，改不透明等于放弃这个效果（浮层会变成两块深色板子挡住图） |
| 让浮层不再"补画父背景"（自己存一张快照） | 更复杂（要维护快照失效），收益不明确 |
| 窗体级 `WS_EX_COMPOSITED`（全屏合成） | **否**。重锤：它会改变整个窗体的绘制方式，在一块要画上万图元的画布上反而可能变慢 |
| 把浮层从"子控件"改成"画布自绘" | **否**。会失去 WinForms 的按钮交互（悬停/按下/命中都要自己写） |

## 五、顺带改掉的一处：`RefreshKWindow()` 去掉同步阻塞

`RefreshKWindow()` 原来是 `kWindowControl1.Refresh()`（= `Invalidate(true)` + `Update()`），
`Update()` 会**同步**把 `WM_PAINT` 处理完才返回 → 数据变化后若紧接着还有消息
（连续点选、批量操作逐项刷新），每一次都要等一整帧画完，中间没有"合并多次重绘"的机会。
已改为 `Invalidate(true)`（异步标脏、参数仍为 `true` 以保住浮层重绘）。

> ⚠ **更正一个早先的说法**：我最初举的例子是"滚轮快速连发"，**这不准确** ——
> 滚轮缩放走的是控件内建的 `Viewport.Changed → OnViewportChanged → Invalidate()`，
> **不经过** `RefreshKWindow()`。
> 这次改动的实际收益落在"**数据变化后的刷新**"这条路径上（选点 / 切图层 / 清空选点等
> — 共 25 个调用点），**不是滚轮手感**。滚轮那边本来就是异步的。
