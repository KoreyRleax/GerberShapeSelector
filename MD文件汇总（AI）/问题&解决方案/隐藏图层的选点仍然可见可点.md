# 隐藏图层的选点仍然可见可点

- **首次记录**：2026-09-21
- **状态**：（已完成 2026-09-21）AI 侧编译验证通过；待用户实机逐条验收
- **关联**：`MD文件汇总（AI）/任务&需求/R-20260921-01-多图层选点与图层顺序.md`；
  `MD文件汇总（AI）/待办/待办清单.md` T21

## 一、现象

> **用户原话**：
> "当图层被隐藏时，该选点应该也被隐藏，但这里仍然保留；**图层隐藏时，仍然可以选该图层的点**，
> 这是很奇怪的，因为用户看不到。"

复现：在某个图层上选了一些点 → 取消该图层的勾选 →
底图消失了，**但这些选点还画在原地**，并且左键点它们仍然能选中 / 取消。

## 二、影响

- 用户看不到的东西却能操作 → 直接违反直觉；点中之后状态栏计数变化，但画面上找不到对应的图形。
- 更隐蔽的连带影响：**框选**会把隐藏图层上的图形收进选点、**多选同类扩散**也会选中它们。
  保存出来的 `circles.json` 里点数比"画面上看得到的"多，用户无法核对。
- 严重度：中高（不影响能选到点，但会让结果与预期不一致）。

## 三、定位过程

1. **先找绘制路径**：底图由 `DrawGerberApertures` 画，它已经按 `layer.IsVisible` 过滤（规则 R1）。
2. **再找选点路径**：选点**不是**底图的一部分，而是**独立画的第二遍** ——
   `DrawSelectedCircles`（Gerber 模式）与 `DrawAllTemplateCircles`（模板模式）。
   **这两处没有查图层可见性** → 底图没了、点还在。
3. **再看选取入口**：一共三个 —— 左键命中（`KWindowControl_KMouseDown`）、右键菜单
   （`KWindowControl_ContextMenuRequested`）、框选（`ApplyRegionSelection` →
   `GetCirclesInSelectedRegion`），外加多选扩散（`HandleMultipleSelect`）。
   它们都只看几何，**不认图层** → "仍然可以选"。
4. 也确认了 `_apertures`（包围盒用）**故意不做可见性过滤** —— 否则隐藏一层会让视图跳动，
   这是 2026-09-19 就定下的设计（`RebuildAperturesFromLayers` 的注释），**不是**本次要改的东西。

## 四、根因

**同一件事（"这个图形属于可见的图层吗"）在四个地方各判了一次，而其中四处漏判。**

具体地说，这个工程里"图层显隐"有两条**互相独立**的绘制路径（底图 / 选点）和三个
**互相独立**的选取入口（命中 / 框选 / 多选扩散）—— 缺少一个统一口径，
所以"只改了其中一处"就必然表现为"有的地方生效、有的地方不生效"。

## 五、解决方案

新增唯一口径，四个地方全部接上：

```csharp
/// 该图形所属图层当前是否可见（读运行期字段，不做图层名匹配）
private bool IsShapeLayerVisible(SelectedCircle shape)
{
    return shape != null && !shape.LayerHidden;
}
```

| # | 位置 | 作用 |
|---|---|---|
| 1 | `DrawSelectedCircles`（Gerber 模式画已选点） | 隐藏图层的选点不画 |
| 2 | `DrawAllTemplateCircles`（模板模式画全部模板点） | 同上 |
| 3 | `DepthForHitTest`（左键 + 右键菜单共用） | 隐藏图层的图形返回 `SkipDepth`，不参与命中 |
| 4 | `GetCirclesInSelectedRegion` | 框选不收隐藏图层的图形（两个调用方共用：真正选中 + 右键菜单显示数量） |
| 5 | `HandleMultipleSelect` | 多选扩散的第一道过滤（与框选限定**链式叠加**，不是覆盖） |

**数据不删**：`_selectedCircles` 与 `_apertures` 都不动 ——
所以包围盒不跳、视图不晃；重新勾上图层，选点原样回来。
（隐藏是临时的视觉操作，不该顺手删掉用户选的几千个点。）

顺带修掉一个真错误：多选扩散的第二道过滤原来写成 `allShapes.Where(...)`
（在**原集合**上过滤，会覆盖掉第一道），改成 `searchSource.Where(...)`，两道过滤才是叠加关系。

## 六、优劣 / 备选方案

| 方案 | 结论 |
|---|---|
| **"不画 + 不选 + 数据保留"**（采用） | 与"隐藏是临时操作"的直觉一致；重新勾上即恢复，无数据损失 |
| **隐藏时把该图层的选点从 `_selectedCircles` 移除** | **否**。用户只是临时把某一层藏起来看别的层，移除等于删数据；而且移除后重新勾上无法恢复 |
| **隐藏图层仍然可选中（只是不画）** | **否**。就是用户报的这个现象：看不见却能点，状态栏数字变了却找不到对象 |
| **隐藏时把选点画成半透明/灰色以示区别** | **否**。绕过了问题本身；用户要的是"这一层暂时不存在" |
| **在 `_apertures` 层面过滤隐藏图层** | **否**。会让包围盒随显隐变化 → 视图跳动（既有设计明确反对，见 `RebuildAperturesFromLayers` 注释） |

## 七、遗留

- 隐藏图层的选点**仍保存在 `circles.json` 里**（这是刻意的，见上）。若下游设备希望
  "隐藏的层不出现在模板中"，那需要在保存端再讨论一次语义 —— 目前没有这样的需求。
- 与之配套的"命中优先级"见 `MD文件汇总（AI）/问题&解决方案/选点只能选到最大圆圈那一层.md`
  （两者共用同一份图层状态数据）。
