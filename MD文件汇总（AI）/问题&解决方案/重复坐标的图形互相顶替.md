# 重复坐标的图形互相顶替

- **首次记录**：2026-09-21（由回归日志暴露；用户同时追问"重复坐标的点怎么处理"）
- **状态**：（已完成 2026-09-21）AI 侧编译验证通过；待实机验证"复用数 ≤ 已选数"
- **关联**：`MD文件汇总（AI）/任务&需求/R-20260921-01-多图层选点与图层顺序.md`；
  `MD文件汇总（AI）/系统架构&协议设计/数据格式-circles.json.md`；

## 一、现象

用户先问"如果有重复坐标的点你是如何处理的"；随后在回归日志里出现这条**自相矛盾**的记录：

```
09:32:09.530  打开工程：从 circles.json 恢复 2 个选点
09:32:09.692  图形缓存构建完成：20188 个图形（其中已选 2 个，复用选点对象 8 个，回填图层 0 个）；图层 6 个，归属失败 0 个光圈
```

**"已选 2 个"却"复用 8 次"** —— 同一个选点对象被当成 8 个图形塞进了缓存。
（正常情况下复用数 ≤ 已选数。）

## 二、影响

- 被顶替的那个图形**整个不在 `_allShapes` 里** → **永远点不中它**（用户表现为"这个点怎么点都没反应"）。
- 被反复复用的那个对象在缓存里出现多次 → 命中测试可能返回同一个对象的多份，
  计数与绘制都可能重复。
- 这是**静默**的：没有报错，只有日志里那个数字不对。

## 三、定位过程

1. 读 `BuildAllShapes`（`MainForm.cs:2308`）的两级索引：
   - `exactIndex` 键 = `ShapeKey(图层, 坐标, 形状)`
   - `looseIndex` 键 = `ShapeKeyLoose(坐标, 形状)`（给 v2.2 以前没有 `Layer` 的老 json 兜底）
2. 遍历 `_apertures` 时，只要键命中就 `shapes.Add(existing)` 并 `continue` ——
   **同一把键可以被多次命中**，而 `existing` 是同一个对象。
3. 于是问题变成"同一图层内，会不会有两个图形算出同一个键"。
   真实 Gerber 里非常常见：**焊盘和它的外形框都落在中心点上**（同坐标、同形状、**直径不同**），
   而 `ShapeKey` 里**没有尺寸维度** → 键完全相同。
4. 佐证：日志里 `复用 8 / 已选 2` 的比值说明确实存在成组的同键图形。

## 四、根因

**图形的唯一键不唯一 —— 少了一个维度。**

```
旧键：ShapeKey = (图层, 坐标, 形状)          ← 同一层同坐标的"焊盘 + 外形框"会撞键
新键：ShapeKey = (图层, 坐标, 形状, 尺寸)    ← 四个维度缺一不可
```

四个维度各自防的是什么：

| 维度 | 少了它会怎样 |
|---|---|
| 图层 | `GBL` 与 `GBS` 常在同一坐标放尺寸不同的图形 → 两层被认成一个 |
| 坐标 | 显然（同时统一 `Math.Round(…,4)`，与保存端同精度，比对即精确相等） |
| 形状 | 同坐标的圆与矩形分不开 |
| **尺寸** | **同层同坐标的焊盘与外形框互相顶替**（本次修的这条） |

后果不是"少画一个"，而是**错位认领**：建索引时键互相覆盖 → 遍历光圈时同一个选点对象被反复复用。

## 五、解决方案

### 5.1 键补上尺寸维度

- 新增 `GetSize()`（`MainForm.cs:2213`）统一把各形状的尺寸折成 `(sizeX, sizeY, sizeR)`：

  | 形状 | 尺寸三元组 |
  |---|---|
  | 圆 | `(直径, 直径, 0)` |
  | 矩形 | `(宽, 高, 0)` |
  | 椭圆 | `(宽, 高, 旋转角)` |

- `ShapeKey` / `ShapeKeyLoose` 都变成含尺寸的元组，并各加两个便捷重载
  （`ShapeKey(SelectedCircle)` / `ShapeKey(Aperture a, double x, double y)`），
  避免调用点手写一长串参数。
- 坐标也统一 `Math.Round(…, 4)` —— 与保存端同精度，于是**从 json 恢复的选点也能走精确键**，
  不再只依赖退化键。

### 5.2 `usedSelected` 兜底（关键）

```csharp
var usedSelected = new HashSet<SelectedCircle>();   // 已经复用过的选点对象
...
if (hit && existing != null && usedSelected.Add(existing))   // ← 最多复用一次
{
    existing.IsSelected = true;
    existing.LayerId = owned ? owner.Id : 0;
    shapes.Add(existing);
    reused++;
    continue;
}
// 否则走"新建图形"分支
```

即使键再撞，也只会"多建一个图形"，而不会"重复认领"。
**缓存里永远是一对一的。**

### 5.3 `IsSingleShapeInShapes` 与键口径对齐

它（判断"是否已在选中集合里"）原来比较 坐标 + 形状 + 尺寸，**没有图层** ——
跨图层同坐标同尺寸的图形会被判成"已经选过"而加不进 `_selectedCircles`
（表现为"选中了却保存不进去"）。补上 `LayerId` 维度，与 `ShapeKey` 口径一致。

### 5.4 日志自检

构建日志现在会在异常时追加提示：

```
复用选点对象 N 个 … ⚠ 复用数(N)超过已选点数(M)，有图形被重复认领
```

## 六、重复坐标的实际语义（回答用户的问题）

| 情形 | 处理 |
|---|---|
| **不同图层、同坐标** | 键含图层 → **各自独立保留**（两条记录）。命中时按叠放取最上层，想选下层就把它置顶 |
| **同图层、同坐标、同形状、尺寸不同** | 键含尺寸 → **各自独立**（本次修掉的正是这条） |
| **同图层、同坐标、同形状、同尺寸** | 键完全相同 → 界面上就是**同一个点**，只被选中 / 保存一次 |

也就是：**同一个键 = 同一个点**，这是唯一一条去重规则。
看到重复坐标不必惊讶 —— 那多半是**不同图层**的点落在同一坐标，本来就该各占一条。

> 🔴 **2026-09-21 补充（本节结论的适用范围被收窄了）**：以上是**模型内**的语义。
> 导出端已**另加一条口径** —— 保存时按**落盘坐标**判重（不含图层、形状、尺寸），
> 同坐标多条会被弹窗拦下，用户裁定"**这种情况不被允许**"（插针机按坐标定位 → 重复插针）。
> 所以"各占一条"只在**编辑期间**成立，**保存时会被告知冲突**。
> 两套口径的分工与理由见 `MD文件汇总（AI）/任务&需求/R-20260921-06-保存前同坐标重复点检查.md`。

## 七、优劣 / 备选方案

| 方案 | 结论 |
|---|---|
| **键加尺寸 + `usedSelected` 兜底**（采用） | 双保险：前者治"为什么会撞"，后者保证"撞了也不出错" |
| 只加尺寸、不加 `usedSelected` | 不够。真实数据里总可能有"尺寸也分不开"的重复（同光圈在同一坐标被重复绘制），那时又会重复认领 |
| 只加 `usedSelected`、不改键 | 能用，但每次撞键都会白建一个对象（21k 图形下浪费可观），而且"同层焊盘与外形框"仍然只有一个能被选中 |
| 用尺寸拼成一个 `double` 签名（`d + w*1e4 + h*1e8`） | **否**。浮点拼接会有碰撞与精度问题，元组更直白 |
| 把尺寸并进 `ShapeKey` 而不管放置顺序 | **否**。键的"维度"必须是**语义维度**，尺寸是独立的第四维 |

## 八、遗留

- 若将来出现"同图层、同坐标、同形状、同尺寸但有意义的两个图形"（例如同一个光圈在同一坐标
  被 Gerber 重复绘制两次），当前处理是**合并成一个点**。这是刻意的（重复绘制本就是同一物理点），
  但如果下游需要区分，需要回到这里重新讨论。
- 键的维度以后若再增加（例如加上"光圈 ID"），**三处使用点必须一起改**：
  `BuildAllShapes` 建/查索引、`ApplyRegionSelection` 建/查集合、`IsSingleShapeInShapes`。
