# 参数设置点「确定」会静默改写工程归属

- **发现日期**：2026-09-21（排查「模板文件保存路径还有必要保留吗」时顺带查出）
- **状态**：（已修复 2026-09-21）随 `MD文件汇总（AI）/任务&需求/R-20260921-04-移除模板保存路径设置.md` 一并处理
- **影响面**：会**写错落点**导致选点数据分叉，且用户看不出是哪一步丢的
- **同一类缺陷的另一个入口**：`MainForm.LoadSavedPath()`（启动时）—— 那条**早于本轮已修**
  （代码注释里还留着当时的说明），本轮修的是漏掉的那条

## 一、现象

复现路径（每一步都是正常操作）：

1. 「文件 → 打开工程」打开工程 **A**（目录 `D:\板子\1516601`），里面有选点
2. 「视图 → 参数设置」，**只是进去改一个颜色**（或什么都不改）
3. 点「确定」
4. 点「保存」

**期望**：内容写回 A（`D:\板子\1516601\circles.json`）。

**实际**：内容写去了 `DefaultSavePath\<DefaultSavePath 的目录名>`——
`DefaultSavePath` 通常是 `…\GerberParserSmartV4.0\template`，
于是落点变成 `…\template\template`。**工程 A 里的 `circles.json` 还是旧的（甚至根本没有）。**

状态栏还照样显示 `模板已保存: D:\…\template\template` ——
它是完整路径，看起来毫无异常，但没人会去核对那是不是他打开的那个工程。
**下次打开 A，看到的是改动前的选点，用户只会以为"白干了一场"。**

## 二、根因

三层，缺一层都构不成这个现象：

### ① 直接原因：对话框的回调直接写了"工程归属"

```csharp
// btnParamSetting_Click（已删除）
if (!string.IsNullOrEmpty(newPath) && Directory.Exists(newPath))
{
    _currentTemplatePath = newPath;      // ← 一个"全局界面设置"顶掉了工程归属
}
```

`_currentTemplatePath` 是**工程归属的唯一依据**（「保存」靠它决定就地写回哪个目录）。
在一个"只管配色"的对话框的确定回调里改它，等于给保存落点开了第二个入口。

### ② 那个 `newPath` 是全局默认值，不是当前工程

`ParamsForm.txtSavePath` 里填的是 `GetBaseTemplatePathFromSettings()`，
也就是 `Properties.Settings.Default.DefaultSavePath` —— 一个与"当前打开了哪个工程"**完全无关**的全局值。

而且这一步是**必然**发生的：`ParamsForm_Load` 在 `ShowDialog()` 触发时才执行，
而主窗体是在 `ShowDialog()` **之前**调 `SetSavePath(GetCurrentSavePath())` 的 ——
**Load 晚于 SetSavePath，文本框里的当前工程路径被无条件覆盖掉了。**

> 换句话说：主窗体那段"把当前保存路径传给参数窗体"的代码**从来没有生效过**（死代码）。
> 它让人以为"文本框里显示的就是当前工程目录"，实际上只是把主窗体的那段意图洗掉了一层。

### ③ 后果为什么这么难查

- `GetProjectName()` 在 `_currentTemplatePath` 非空时返回**它的目录名**。
  归属被改成 `…\template` 之后，工程名就成了 `template`，落点顺势变成 `…\template\template`——
  **多套一层**，日志里只看到路径，看不出这是错的。
- 覆盖确认框弹的是**完整落点**，但只在"目录已存在"时才弹；
  第一次写进 `…\template\template` 是**新建**，一声不响就建好了。
- 中间没有任何异常、没有日志告警 —— `KLog` 里那行
  `参数设置后更新当前模板文件夹路径: …` 甚至把错误状态**当成正常状态记了下来**。

## 三、解决方案

分两步，缺一不可：

**① 删掉回写归属的那 5 行**（治症状）

`btnParamSetting_Click` 只管配色 —— 它现在的全部职责是"回读三个颜色 → 存设置 → 重绘"。

**② 删掉 `DefaultSavePath` 设置项本身**（断根）

只要这个全局默认值还存在，就总有机会被拿去顶替归属。
本轮把它连同 `GetBaseTemplatePath` / `GetCurrentSavePath` / `UpdateSavePath` / `LoadSavedPath`
一起删掉，「保存」的落点从此只有两个来源：

- **有归属** → 就地写回 `_currentTemplatePath`
- **无归属** → 弹目录选择器，由用户**当场**指定

于是"一个与当前工程无关的路径"在结构上不再可能参与落点判定。
详见 `MD文件汇总（AI）/任务&需求/R-20260921-04-移除模板保存路径设置.md`。

## 四、优劣 / 备选方案

| 方案 | 内容 | 判断 |
|---|---|---|
| **① 全删设置项**（本轮选的） | 删回写归属那 5 行 **+** 删掉 `DefaultSavePath` 及其全部代码；无归属时弹选择器 | ✅ **根治**：落点只剩"当前工程目录 / 用户当场选择"两个来源，这类缺陷在结构上不可能再出现。代价：新工程首次保存多一次点击（换来的是"存到哪"由用户当场决定） |
| ② 只删那 5 行，设置项留着 | 治症状 | ❌ 症状确实消失，但设置项**唯一剩下的生效点**（无归属时悄悄落到某个全局目录）仍是"保存到哪说不清"的老来源。而且它仍然是这类"顶替归属"代码的入口 |
| ③ 参数窗体的路径行改成**只读显示** | 显示当前工程归属、不给编辑 | ❌ 表面上比原来安全（没有可写回的值了），但那个只读值该显示什么？显示 `DefaultSavePath` 与工程无关、显示 `_currentTemplatePath` 与"模板保存路径"这个标签矛盾。**两个语义拧在一个控件里，怎么都别扭** |
| ④ 把"改落点"做成显式动作 | 菜单加「工程 → 移动到…」，语义清楚，与「另存到」并列 | ⏸ 这是**真正合理的形态**，但当前没有这个需求（用户要的是删掉设置项）。若将来需要"换地方"，「另存到」已经覆盖了 —— 不再单开入口 |
| ⑤ 无归属时不弹框，直接用图层所在目录 | 新建后第一次保存就地写进 Gerber 素材目录 | ❌ 会把 `circles.json` 写进**上游给的原始素材目录**，素材一更新就难分离；只读目录还会直接写失败。详见需求文档 §六 同条 |

**为什么不做"两个入口都保留、但只在无归属时读设置项"**：
这正是被否掉的方案 A（见需求文档 §六）。设置项是**全局的、看不见的**，
用户点「保存」时既看不到它、也想不起它 —— "没归属时落到一个我看不见的地方"
与"没归属时问我一句"相比，后者在任何一次误操作下都不会丢数据。

- **编译**：`dotnet build -c Debug -p:Platform=x64` → **0 Warning / 0 Error** ✓
- **日志侧**：`参数设置后更新当前模板文件夹路径: …` 这行字在源码里已消失，
  不会再出现"把错误状态记成正常状态"的记录 ✓
- **实机复现验证**（**待你执行**）：按 §一 的四步走一遍 →
  第 4 步的落点应当是**工程 A 自己**；状态栏显示的路径也应当是 A 的路径。

## 六、教训

1. **"顺带写回全局状态"是危险动作。** 在一个"只管界面设置"的对话框回调里，
   去改一个语义完全不同的字段（工程归属）—— 这类代码写的时候看着"顺手"，
   出事的时候完全没有征兆。**改状态前先问：这个字段的语义属于这个界面吗？**
2. **要检查"这段赋值是否真的生效"。** `SetSavePath(GetCurrentSavePath())` 那段代码
   **从未生效过**（被 `ParamsForm_Load` 覆盖）。死代码不会报错，
   它只会让人以为"这里已经处理过了"，从而在别处放松警惕。
   → 排查"值为什么不对"时，先确认**写进去的那个值还在不在**。
3. **同类缺陷要一次找全。** `LoadSavedPath()` 那条（启动时把 `DefaultSavePath` 写进归属）
   在本轮之前就被注释掉并修掉了，`btnParamSetting_Click` 这条却留着。
   代码注释里甚至写着"参数设置窗体要显示当前保存路径，走 `GetCurrentSavePath()` 自己的回退即可"
   —— 说明当时已经意识到这个设置项的语义纠缠，**只是漏了另一个入口**。
   → 修一个写入点时必须 `grep` 同类写点，不能只修眼前那一处。
4. **"看起来正常的提示"比"报错"更危险。** 状态栏显示的是完整路径，
   覆盖确认框也弹完整落点 —— 但用户不会去核对。
   **提示里必须包含"这是哪个工程"**，而不只是"写到了哪个路径"。
   （这也是「保存」的无归属分支改成"当场问"的另一个理由：用户的注意力就在那一次选择上。）
